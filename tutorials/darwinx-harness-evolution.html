DarwinX: Evolving Agent Harnesses Through Natural Selection

18 min read · arXiv:2608.07545 · arXiv · X post · Self-Improving Agents & Harnesses

TL;DR

  • "DarwinX: Evolving Agent Harnesses Through Natural Selection" (arXiv 2608.07545; Yifan Zhang, Yutong Dai, Juntao Tan, et al., with Silvio Savarese, Ran Xu, Zeyuan Chen — Salesforce AI Research/Agentforce) treats harness self-evolution as population selection: an archive of lineages, a preserve-and-extend contract admitting a child only if it solves something new without regressing what its parent solved, and cross-lineage recombination of complementary specialists. The base model is frozen; fitness is each benchmark's own verifier at avg@\(k\) — no gold solutions, no hand-picked winners.
  • One loop adds ~17 points on average across four regimes of increasing train/test separation: Terminal-Bench 2.1 rises 75.5% → 83.2% on frozen GPT-5.5 (84.7% on GPT-5.6 Sol, the verified-leaderboard frontier) but evolves on its own evaluation set; TerminalWorld held-out reaches 68.3% on 41 tasks disjoint from the 94 it evolved on; WebArena-Infinity real-task pass@1 goes 43.5% → 93.0% audit-clean after evolving only on synthetic intents; and the TB2.1 harness transfers unchanged to SWE-bench Verified at 84.2%.
  • The cleanest evidence for keeping a population: on TerminalWorld the in-loop proxy saturates at 1.000 yet held-out is 68.3%, and four proxy-fit specialists solve 24–27 held-out tasks each while their merge solves 28. Greedy search would have collapsed onto an overfit incumbent.

Why this matters

Nearly every self-improving-agent system — SICA, DGM, HarnessX, the skill/prompt optimizers — has converged on the same inner loop: roll out, reflect, propose a bounded edit, gate against a regression signal. DarwinX asks the complementary question this reading list keeps circling: what selection process should wrap that loop? Two failure modes motivate the answer. Path dependence: single-lineage self-editors get biased by early edits and plateau (Robeyns et al. report this for SICA). Cross-task interference: an edit that fixes one task family silently regresses another, and the wider the distribution, the sharper the pathology.

The positioning against DGM is the sharpest way to see the contribution. DGM already has an archive with stochastic parent selection, but it mutates one parent at a time and scores the child only against that parent — complementary lineages are never brought back together, and a gain carries no obligation to hold what it displaces. DarwinX makes that obligation explicit and adds a merge operator with a set-theoretic acceptance criterion. The paper's closing line is the punchline: harness selection "turns evaluation compute into durable capability."

The core idea

In plain English first. The weights stay frozen; what evolves is the harness — the program around the model. It spans two editable layers: a skill layer (prompts, memory, distilled knowledge) and a code layer (tools, control flow, the agent loop). Every edit is additive, so a lineage accumulates capabilities rather than laterally rewriting itself.

The vocabulary, defined as used below. A variant is one harness; a lineage is a chain of variants each derived from the last; the archive is every variant ever scored, losers included, arranged as a tree. Each variant has a solved set — the tasks it actually solves — and comparing a child's to its parent's is how children get filed:

  • improvers (strictly more) and neutral children (the same set) preserve every inherited solve and stay eligible as ancestors and as merge parents;
  • stepping stones (strictly fewer) and archived trades (some solves swapped for others) may not be built on, and feed back only distilled lessons;
  • a specialist solves a task no sibling does — possibly a globally weaker harness holding the one edit that, combined with another branch's, unlocks a task neither solves alone.

Two rules give the search its character. The preserve-and-extend contract admits a child only if it gained something on net and gave up almost nothing. The merge operator composes complementary variants' edits onto their common ancestor and keeps the result only if it solves the union of what they solved. Together they bet that the useful object at the end of a search is a population, not a single incumbent.

How it works

The loop in one sentence. Each generation DarwinX picks one harness out of the archive, makes one additive edit to it, re-runs it on tasks, and keeps it as a building block only if it solved something new without losing anything its parent had. Everything else is detail about which parent, which edit, and how "without losing anything" is measured.

One generation, start to finish

A worked example on Terminal-Bench 2.1 with a frozen GPT-5.5 base (reconstructed from the paper's routing rule, per-cluster gains, and list of evolved skills — it reports these separately and never narrates a generation end to end). The question: given a branch that keeps almost solving its machine-learning tasks, what edit does the system choose, and what must be true before that edit may influence anything else?

Step 1 — Which harness gets to be edited? Not the highest scorer. Variants are screened on different rotating task subsets, so raw scores are not comparable across the archive; what is comparable is how much a lineage has gained since the root. Most of the time the loop takes the leader by that measure, drawn only from fully confirmed variants; the rest of the time it draws more widely, so losing branches stay reachable.

Step 2 — What evidence should drive the edit? The branch is assigned a capability cluster — a task family such as machine learning and scientific computing, or low-level systems. On Terminal-Bench 2.1 those are exactly where the frozen base has headroom, gaining +14.8 and +13.8 points over the run while already-strong clusters barely move. Every task in the cluster has been attempted several times by the parent, and that record of repeated attempts decides what the proposer may look at:

The parent's repeated attempts at a task What that means Evidence handed to the proposer
all pass a reliable solve none — leave it alone
some pass, some fail the variance band: the capability exists; the consistency doesn't the agent's own passing and failing runs, side by side
none pass a wall — there is nothing to contrast a reference solver's successful run
anything else an ordinary failure a summary of the failed runs, naming the missing capability

Routing is neither learned nor heuristic: it falls out of the record. And because the partition is recomputed as the harness improves, a task migrates from wall to variance band to reliable, and its signal changes with it. Here several machine-learning tasks sit in the variance band, so the proposer gets the parent's own passing and failing rollouts on one of them. The contrast is legible: the passing runs checked the graded artifact before declaring themselves done.

Step 3 — Make exactly one additive edit. The proposer writes that observation into the skill layer as a reusable capability — verify the graded artifact against the acceptance contract before finishing — rather than patching the task in front of it. That is the shape of everything that survived here: all seven skills the run added belong to one verification/artifact-contract family (derive the acceptance contract, verify the graded artifact, ground outputs in real tool execution, fix-and-recheck), and none adds domain knowledge.

Step 4 — Screen the child, and ask the gate two separate questions. The child is re-run at avg@3 on a rotating task subset — three attempts per task, graded by the benchmark's own verifier, averaged — giving a solve rate per task for it and its parent. The gate then asks two questions it deliberately does not merge into one score: did it gain anything on net? and did it give anything up? Admission needs positive net gain and total give-up under a fixed bound, so a child cannot buy back a regression with a bigger win elsewhere. A reasoned verifier agent makes the call from the trial evidence plus shared memory, returning promote or revert.

Step 5 — Promoted is not the same as trusted. The selector is two-speed: permissive about trying, strict about trusting. A promoted child enters the tree on a bounded-downside, possibly noisy signal, but before it may steer future search — be the leader Step 1 exploits, or a merge parent — it must survive a re-test at full avg@5 plus a preservation probe re-sampling the lineage's known solved set. That is how the search moves fast without letting luck accumulate.

Step 6 — File it, and keep it either way. The child is classified by solved set and added to the archive, which never deletes anything; the outcome updates the shared memory both proposer and verifier read next time. Here it is an improver — and across the full run the six newly solved tasks cost roughly 2× the turns and 4× the tokens of verify-and-retry effort while the 69 already-solved tasks stay flat at 13 turns against 12, so the added capability fires only where it is needed.

The machinery behind steps 1 and 4

Figure 3 from the paper: the mutation loop and its three learning signals (left), variants classified by how their solved set changes (middle), and the merge operator (right).

Step 1, the parent-selection rule.

\[p^* \sim (1-\beta)\,\delta_{\arg\max_{v \in \mathcal{S}} G(v)} + \beta\,\mathrm{Broaden}(\mathcal{P})\]

Symbol by symbol: \(p^*\) is the parent drawn this generation; \(\mathcal{S}\) is the steering set of variants that have passed full confirmation; \(G(v)\) is variant \(v\)'s cumulative lineage gain, defined recursively as \(G(c) = G(p) + g(c)\) — a child inherits its parent's running total and adds \(g(c)\), how much it gained over that parent (made precise in the next block); \(\delta_{\arg\max}\) is a point mass on the confirmed variant with the highest such total, i.e. "take the leader"; \(\mathcal{P}\) is the wider population of every scored variant, \(\mathrm{Broaden}(\mathcal{P})\) a spread-out draw over it; and \(\beta\) is the exploration rate. (Note the letter collision: this \(\delta\) is a point mass, unrelated to the regression bound \(\delta\) below. The paper reuses the symbol.)

Step 4, what the gate actually computes. Write \(\hat{p}_t(v)\) for variant \(v\)'s measured solve rate on task \(t\). For a child \(c\) of parent \(p\):

\[\Delta_t = \hat{p}_t(c) - \hat{p}_t(p), \qquad g(c) = \sum_t \Delta_t, \qquad R(c) = \sum_t (-\Delta_t)_+\]

\(\Delta_t\) is the per-task change; \(g(c)\) is the net gain, the signed sum over screened tasks, so wins and losses cancel; \((x)_+ = \max(x,0)\) keeps only positive values, so \(R(c)\) — the regression mass — counts only what the child gives up. The contract admits a child iff \(g(c) > 0\) and \(R(c) \le \delta\), where \(\delta\) bounds tolerable regression. The paper never states a numeric \(\delta\), so the strictness of its headline contract cannot be reproduced from the text.

Two properties of \(\hat{p}_t\) do more work than the algebra. The same grader that scores the final report scores the search — no gold solutions, no hand-picked winners. And timeouts at a task's declared budget count as real capability failures, so a variant cannot buy fitness by being slow; only infrastructure errors outside the agent's control are separated out.

The verdict itself is not a threshold but an adjudication:

\[\mathrm{verdict}(c) = f\big(g, R, \mathcal{E}, K_g\big) \in \{\text{promote}, \text{revert}\}\]

where \(f\) is a reasoned verifier agent, \(\mathcal{E}\) is the trial evidence from screening, and \(K_g\) is the population's shared memory at generation \(g\).

The three routed signals, in the paper's notation. Failure-derived diagnosis (\(\nabla\)) summarises failed trajectories \(\tau\); teacher-derived demonstrations (\(\pi^*\)) distil a reference solver's successful trajectory \(\tau^*\); self-derived contrast (\(A\)) compares the agent's own passing and failing rollouts \(\{\tau_i\}_{i=1}^{k}\) on one task. The signal is a plug-in interface: any evidence source that can explain how a harness should change is admissible, and these three are merely the native ones. The Step 2 table is the routing rule in full.

The merge operator. When variants \(v_1,\dots,v_n\) solve complementary tasks, a merged child is materialised from their common ancestor \(H_0\):

\[H = H_0 \oplus \Delta, \qquad \Delta = \Delta_{\text{code}} \oplus \Delta_{\text{skill}} \oplus \Delta_{\text{prompt}} \oplus \Delta_{\text{tool}}\]

\(H_0\) is the ancestor both parents descend from; each \(\Delta_{\text{layer}}\) is the additive edits accumulated at that layer; \(\oplus\) is layer-wise composition — what makes merging tractable at all, since additive edits to different layers rarely collide. Acceptance is set-theoretic: writing \(S(v)\) for a variant's solved set, keep the merge iff \(S(\text{child}) \supseteq \bigcup_i S(v_i)\) — it may add coverage, never trade it. Archived specialists each contributing one unique solved task count as genetic material, more than two parents may be combined, and the merged child is confirmed under the same avg@\(k\) rules as any mutation.

Shared memory. A failure-mode classifier labels each trial (timeout-setup, wrong-output, tool-error, …) and aggregates the generation's dominant themes: \(K_{g+1} = \mathrm{Agg}(K_g, \text{worked}, \text{regressed}, \text{themes})\), where \(K_g\) is the memory carried into generation \(g\), worked and regressed that generation's outcome lists, themes the dominant failure labels, and \(\mathrm{Agg}\) the aggregation into the next memory. Both proposer and verifier read it, which is what lets the search target systemic bottlenecks rather than per-task patches: "setup cost dominates timeouts → build an efficient-setup capability."

What the four regimes test, and what is never measured

Evaluation is a ladder of four regimes ordered by how far the evolution signal sits from the test, and the differences between them matter more than the headline numbers.

Regime What evolution sees What is reported Separation
Terminal-Bench 2.1 (frozen GPT-5.5) the same 89-task suite — avg@3 screening on rotating subsets, avg@5 confirmation on the full suite official avg@5 on those same 89 tasks none
TerminalWorld (frozen Opus 4.8) 94 training tasks under adaptive avg@\(k\) subsets, frozen before the split is touched single-attempt pass@1 on 41 disjoint tasks disjoint task split
WebArena-Infinity (frozen GPT-5.5) 300 synthetic intents, scored by an LLM judge (avg@3 screen, avg@5 confirm) deterministic pass@1 on 1,260 real tasks across ten applications distribution and reward source
SWE-bench Verified (frozen Opus 4.8) nothing — the best TB2.1 harness runs unchanged official test harness, all 500 issues no evolution at all

Three pieces of fine print matter. On Terminal-Bench 2.1 there is no split whatsoever; withholding the reference solutions means the harness can change how the agent works but cannot encode answers — a real constraint, not a held-out set. On WebArena-Infinity the synthetic intents come from each application's own description document via a pipeline that never reads the benchmark's task suites at any stage (1,080 two-model seeds → 11,279 raw intents → 8,013 after quality/Jaccard-0.70/TF–IDF filtering → 5,332 in served apps → a balanced 25-per-app draw of 300), deduplicated intra-pool only, so no evaluation intent can be regurgitated; on TerminalWorld, likewise, no held-out reward reaches selection. And SWE-V transfer runs one way only: the sole in-loop SWE-V signal available scored trajectory completion rather than official test resolution.

Beyond the regimes, three things the design promises are never measured. The merge operator paid off in exactly one regime: on WebArena-Infinity the gate keeps 26 iterations and reverts 36, recombination is attempted repeatedly, and every merge is reverted — the entire 49.5-point gain accrues along a short single primary lineage, which is what a single-lineage self-editor would have produced. None of the three components the paper is about has been ablated: the authors concede that "the archive, parent selector, recombination operator, and inference effort are not independently randomized," so "population beats single lineage" is a plausible system-level claim rather than a measured one. Total evolution compute is never reported — no generation count, no trial count, no token or dollar figure — though avg@3 screening plus avg@5 confirmation plus preservation probes over 89 tasks implies a large bill for a method pitched as turning evaluation compute into capability (inferred from the protocol description — verify in the paper).

Initialize archive A = {base harness H_base}, shared memory K = {}
For each generation g:
  p* ← sample parent: exploit argmax lineage-gain G over confirmed set S
       (prob 1-β), else Broaden over full population P     # eq. above
  assign p*'s branch a capability cluster (e.g. numerical-ML, low-level systems)
  partition cluster tasks by p*'s k-sample record:
    reliable solves | variance-band | walls
  pick signal: wall → teacher trajectory π*; variance-band → self-contrast A;
               else → failure-derived diagnosis ∇
  c ← Propose(p*, K): one additive edit (prompt/skill/tool/control-flow)
  screen c at avg@3 on a rotating task subset → per-task p̂_t(c)
  compute g(c), R(c); verdict ← f(g, R, evidence, K)
  if verdict = promote:
      preservation probe: re-sample lineage's known solved set
      confirm at full avg@5 before c may steer future search
  classify c by solved-set: improver / neutral / stepping-stone / archived
  add c to archive A (never delete); update K with worked/regressed/themes
  periodically: find complementary specialists {v_i}, merge H0 ⊕ ⊕_i Δ_i,
      keep merged child iff S(child) ⊇ ∪_i S(v_i), same confirmation rules
Final agent ← best confirmed node (or merged variant) at official avg@k

Results

  • Terminal-Bench 2.1: 75.5% → 83.2% avg@5 on frozen GPT-5.5 (+7.7; +5.2 over the neutral Terminus-2 harness at higher effort on the same base), and 84.7% on GPT-5.6 Sol at medium effort — above Claude Code + Fable 5 (83.8% at xhigh) on the verified leaderboard. No cluster regresses beyond noise: the empirical footprint of the contract.
  • TerminalWorld held-out: 28/41 (68.3%) on Opus 4.8 vs 25/41 base and 65.9% Claude Code; the training proxy saturated (0.505 → 1.000) with a 31.7-point generalization gap, and the merge of four specialists (24–27 solved each) is what wins.
  • WebArena-Infinity: audit-clean pass@1 43.5% → 93.0% (+49.5 matched-model; +6.9 over GPT-5.5 + Browser Use, the strongest same-model baseline). Capability and compliance rise together: invalid trajectories fall 293 → 17, and the evaluation-plane, privileged-host, and exploit mechanisms disappear entirely.
  • SWE-bench Verified transfer: 421/500 (84.2%) official pass@1, +3.4 over a fix-skill reference harness, with zero SWE-V feedback.
  • The reward-hacking audit: no harness-level cheating found; one confirmed shortcut in 370 rewarded trajectories was a per-trial policy lapse, not an evolved exploit; and under the strictest diagnostic (every task-budget timeout counted as capability failure) TB2.1 still reads ~82%, six above base.

How it connects

  • Recursive Harness Self-Improvement: single-lineage recursion — each generation's harness builds the next. DarwinX targets exactly that design's path dependence, and TerminalWorld's specialists-beat-incumbent result is the empirical case for the population.
  • Living-Harness gates episode-level commits into memory and a state graph; DarwinX's preserve-and-extend contract plus preservation probe is the same discipline lifted to population-level variant admission.
  • EvoHarness-RL: the RL answer to the same question — train harness usage into the policy with weight updates. DarwinX is the pure-inference dual: no gradient, selection only; the hybrid is the paper's own Appendix E sketch.
  • Hyperagents: the mirror image — DGM-H makes the variation machinery editable and keeps admission trivial (compiles → archived); DarwinX freezes variation and puts all the design into admission.
  • Ouroboros: the other admission-heavy system, gating on a reviewer panel's reading of the diff rather than on measured solve sets — procedural versus empirical evidence for the same decision.
  • No Universally Best Harness for Automated Discovery (this list): if no single harness dominates, single-incumbent search optimizes a non-existent object; Figure 6 is the direct evidence.
  • Rethinking Harness Evolution: Gains Come from Repeated Sampling: the strongest skeptical prior against this genre. DarwinX's answer is architectural — avg@k confirmation, preservation probes, held-out/audited reporting — but TB2.1 remains test-time evolution on the evaluation suite, so the concern applies most to the headline number and least to TerminalWorld/WAI.

Critical take

The matched-model deltas are real, but read the baselines carefully. On WebArena-Infinity the base harness (Monet, the authors' own proprietary agent) is a coding agent bolted onto a browser scoring 43.5% where Browser Use on the same model scores 86.1% — the +49.5 headline is mostly recovery from a weak start; the honest SOTA margin is +6.9. The recombination story is thinner than the framing, for the reasons recorded above: every WAI merge was reverted, so on the paper's largest gain the population contributed nothing, and merge demonstrably paid off only on TerminalWorld — where the margin over Claude Code is one task (McNemar \(p = 1.0\)) and over the base three (\(p = 0.45\)). With no component ablations and no compute figure, the system-level claim outruns its evidence. The procedure is also base-sensitive (TerminalWorld on GPT-5.5 lands at 56.1%, below Terminus-2's 61.0%; Opus is the reported headline), and Monet is proprietary, so nothing here is reproducible. The reward-hacking audit is genuinely better than the field's norm, though: selection that re-verifies wins appears to select against fragile verifier-gaming, and WAI's 293 → 17 invalid-trajectory drop is the first time in this tracker that capability and compliance have visibly risen together.

If you remember three things

  1. Selection rule over inner loop: everyone shares the rollout–reflect–edit–gate loop; DarwinX's contribution is the wrapper — admit a child only if \(g(c) > 0\) and \(R(c) \le \delta\), keep every variant in an archive, merge complementary specialists, and require \(S(\text{merged}) \supseteq \bigcup_i S(v_i)\).
  2. Two-speed trust: promote on bounded-downside noisy evidence, but let a variant steer only after full avg@k re-confirmation plus a preservation probe on the solved set — recall during exploration, precision during evaluation.
  3. The population absorbs proxy overfitting — where it runs at all: TerminalWorld's in-loop score saturated to 1.000 while held-out was 68.3%, and the merge of four non-best specialists beat every individual. But on WAI every merge was reverted, and the archive, selector and merge operator are never independently ablated, so read "archives beat incumbents" as one 41-task datapoint.
