SAGA: Accelerating Scientific Discovery with Autonomous Goal-Evolving Agents

14 min read · arXiv:2512.21782 · arXiv · Self-Improving Agents & Harnesses

Paper: arXiv 2512.21782 (v2, Mar 30 2026; v1 Dec 25 2025), by Yuanqi Du, Botao Yu, Tianyu Liu, Tony Shen, Junwu Chen, Jan G. Rittig, Kunyang Sun, Yikun Zhang and 20 others, with senior authors Teresa Head-Gordon, Carla P. Gomes, Huan Sun, Chenru Duan, Philippe Schwaller and Wengong Jin (Cornell, Ohio State, Yale, SFU, EPFL, Berkeley, Northeastern, Broad Institute, Deep Principle). Code at github.com/btyu/SAGA, MIT. Grounded in the full arXiv HTML — main text, Methods, and Supplementary S1–S7.

TL;DR

  • Every optimization-based discovery agent assumes the objective is given. SAGA attacks that assumption with a bi-level loop: an outer loop of LLM agents analyzes optimization outcomes, proposes new objectives, and compiles them into executable scoring functions — Dockerized MCP modules written after web research — while an inner loop runs conventional search under whatever objectives currently exist.
  • Wet-lab validation, rare in this literature: 28 synthesized molecules yielded 4 with >80% E. coli growth inhibition at 128 µg/mL with polymyxin B, one of which (compound 8) is non-cytotoxic in HEK293 and HepG2 with Tanimoto similarity 0.28 to all known antibiotics. 24 BLI-tested nanobodies yielded three de novo PD-L1 binders, \(K_D\) 300–400 nM.
  • The result that should change your priors: no single in-silico metric separated binders from non-binders (all p > 0.05), but the composite objective SAGA wrote itself did (p = 0.03). The agent did not just search better — it discovered a better surrogate. That is also what makes SAGA the odd one out as a TTT baseline: the thing being adapted at test time is the reward, not the policy or the program.

Why this matters

For a programme on test-time training for code optimization, SAGA is the useful outlier. The other baselines in this batch — CORAL, AdaEvolve, AdaExplore — hold the objective fixed and compete on how well they search it. SAGA argues the fixed objective is the bottleneck: optimization models "exploit gaps between models and reality, producing solutions that maximize predicted scores while missing important practical considerations that experts would recognize." That is reward hacking, restated as a methodology problem.

Code optimization looks immune — runtime and pass rate are not proxies, they are the thing. But that immunity is only as strong as your harness: optimize wall-clock on a fixed timer and you get cache-warming and input-specialization; optimize pass rate on visible tests and you get test-shaped code. SAGA's own control makes the failure mode concrete — with objectives frozen, its optimizer over-optimizes antibacterial activity and drug-likeness collapses. So read SAGA less as a competitor to your TTT loop than as evidence for why your objective needs an audit loop of its own, and as a demonstration that when the target moves, cross-run scores stop being comparable. That is the moving-target problem Evolving Benchmarks confronts on the evaluation side, handled here with much less rigor.

The core idea

Treat objective design as the outer problem and candidate design as the inner one. Formally (reconstruction — the paper describes the bi-level structure in prose and gives no framework-level equation):

\[\max_{\mathcal{O}}\ \mathrm{Eval}\big(y^{\star}(\mathcal{O})\big)\qquad\text{s.t.}\qquad y^{\star}(\mathcal{O})\in\arg\max_{y}\ \sum_{o\in\mathcal{O}} w_{o}\,s_{o}(y)\]

where \(\mathcal{O}\) is the current objective set with weights \(w_o\) and agent-written scoring functions \(s_o\), \(y\) is a candidate (a SMILES string, a nanobody sequence, a 200 bp enhancer, a crystal formula, a flowsheet), and \(\mathrm{Eval}\) is a held-out metric suite the system never sees during a run. The inner argmax is ordinary optimization; the outer max over \(\mathcal{O}\) is what SAGA automates. The paper's own metaphor: the inner loop is thinking fast, the outer loop thinking slow.

How it works

Four modules plus a selector. The Planner (gpt-5-2025-08-07) turns the natural-language goal, optional context and the previous analysis report into concrete objectives, each with a description, direction and optional weight, in three types: candidate-wise, population-wise, and filter (binary hard constraints). The Implementer first tries to match each objective to an existing scoring function by LLM semantic comparison; when nothing matches it web-researches relevant methods and packages, synthesizes Python against a standard interface (via Claude Code with sonnet-4-5), and tests it on sample candidates. Every scoring function ships as a Model Context Protocol module executing in a Docker container — dependency isolation, reproducibility, and safe execution of code an LLM just wrote. Objectives judged uncomputable bounce back to the Planner, and this retry loop runs to a configurable cap.

The Optimizer is the inner loop and is deliberately swappable — it need only accept (population, objectives with callable scorers) and return an improved population. The default is a plain LLM-based evolutionary algorithm; tasks override it with a nanobody GA (40% CDR swap / 40% single-point / 20% uniform crossover, tournament selection, elitism), an LLM-plus-diffusion-plus-force-field pipeline for crystals, and a trained RL agent over unit operations for flowsheets.

The Analyzer (Claude Code + sonnet-4-5 for candidate investigation, gpt-5 for the report) works two ways: statistically, tracking per-objective mean/variance/trend to detect convergence, stagnation or objective conflict; and empirically, writing and running its own Python plus ToolUniverse domain tools to examine top and bottom candidates for failure modes the current objectives miss. It emits a four-part report — overview, performance, issues, recommendations — and a termination decision. A final selector re-ranks every candidate from every iteration against the original goal, so molecules found under later-abandoned objectives are not lost.

Autonomy levels are the honest part of the design: co-pilot (scientists revise both Planner proposals and Analyzer reports), semi-pilot (humans intervene only at the Analyzer), autopilot (fully automatic). Most results are reported across all three.

What a compiled objective actually looks like — copied verbatim from the supplementary. A composite drug-likeness objective, invented after the Analyzer noticed a −0.054 QED decline and an activity/QED correlation of r = −0.370 in iteration 1:

\[\text{Score}=\text{QED}\times\text{MW\_penalty},\qquad \text{MW\_penalty}=\frac{1}{1+\exp((MW-500)/50)}\]

— a sigmoid discount on molecular weight above 500 Da. For enhancer design, a specificity margin (\(\alpha = 0.5\text{–}1.0\), MPRA expression per cell line):

\[\text{HepG2}-\alpha\cdot\max(\text{K562},\text{SKNSH})\]

And for superhard materials, a piecewise penalty on formation energy \(E_f\) in eV/atom:

\[\text{penalty}=\begin{cases}\alpha\cdot(E_{f})^{2}&\text{if }E_{f}>0\\ \beta\cdot(E_{f}+0.4)^{2}&\text{if }-1.0<E_{f}\leq 0\\ 0&\text{if }E_{f}\leq-1.0\end{cases}\]

The metabolic-stability scorer is the most striking: SMARTS penalties of 0.15 per primary aliphatic amine, 0.12 per morpholine, 0.18 per unprotected phenol — written because the Analyzer found 80% of high-activity iteration-1 molecules contained primary amines and 40% morpholines. Expert review later confirmed it was chemically correct.

# SAGA outer loop (Supplementary S1.2, Phases 0–5)
Input: goal (natural language), context, optional initial objectives + scorers,
       optional initial population; autonomy level in {co, semi, auto}
Phase 0  Init: instantiate modules; store initial population as iteration 0
repeat for iteration k = 1..K:
  Phase 1  PLAN:  O_k <- Planner(goal, context, report_{k-1})
                  # objectives: description, direction, weight, type
                  # if co-pilot: human edits/approves O_k
  Phase 2  IMPLEMENT (parallel over objectives):
             for each o in O_k:
                 s_o <- match existing scorer by LLM semantic comparison
                 if no match: web-research -> write Python -> test
                              -> deploy as MCP module in Docker
             if some o uncomputable: return reasons to Planner, replan (retry cap)
  Phase 3  OPTIMIZE (inner loop, task-specific):
             optionally replace a fraction of the population with random draws
             repeat: generate candidates; batch-score against all s_o;
                     rank by weighted aggregate; keep population size
  Phase 4  ANALYZE: statistics per objective + agent-written code on candidates
             report_k <- {overview, performance, issues, recommendations}
             if semi/co-pilot: human feedback appended
             terminate if goal satisfied / converged / budget exhausted
Phase 5  Finalize: selector re-ranks ALL candidates across ALL iterations
             against the original goal; log objectives, reports, scorer code

Results

Antibiotics (E. coli). Initial objectives: maximize activity (an ensemble of 10 Minimol models trained on internal high-throughput screening), novelty and synthesizability; minimize toxicity and similarity to known antibiotic motifs. Evaluation is 11 held-out metrics with chemist-set thresholds. All three SAGA modes beat instruction-following molecular language models, which "struggle to overcome the optimization difficulty of the antibacterial activity score alone, resulting in chemically valid but inactive molecules." The internal control is sharper: SAGA-Opt — the same optimizer with the outer loop disabled — over-optimizes activity and lands significantly lower average drug-likeness. The invented objectives also transfer: bolted onto REINVENT4, they improve that system too.

Then the wet lab. 28 top molecules were synthesized (>90% purity); compounds 4, 8, 9 and 27 showed >80% growth inhibition at 128 µg/mL with polymyxin B nonapeptide. MIC is 16 µg/mL for compound 4 and 128 µg/mL for the others; only compound 8 showed minimal cytotoxicity in both human cell lines at its MIC, with Tanimoto similarity 0.28 to all known antibiotics (below the field's 0.4 novelty threshold) and no reported activity in SciFinder.

Figure 2 from the paper: (a) SAGA reaches the drug-likeness/activity sweet spot baselines miss; (c) SAGA-Autopilot's metabolic-stability and custom drug-likeness scorers shift the distribution; (e–f) four compounds exceed 80% inhibition at 128 µg/mL with PMB, with dose–response and cytotoxicity in HEK293/HepG2.

Nanobodies (PD-L1). Starting from the standard binder-design metric zoo (ipTM, pTM, min-pAE, pLDDT, hydrogen bonds, salt bridges, ΔSASA, ProteinMPNN score and recovery, CDR–epitope contacts, developability), scored under both AlphaFold3 and Boltz2, SAGA matches or exceeds BoltzGen and Germinal on most metrics with a more balanced profile and 2–5× fewer oracle calls. In semi-pilot mode a scientist flagged low CDR3 pLDDT after iteration 1; SAGA responded by upweighting pLDDT and permitting alpha-helical structure in CDR3. BLI testing of 24 candidates found three true binders, best \(K_D\) 300 nM, CDR3 sequences sharing <20% similarity with all Germinal/BoltzGen designs and everything in SAbDab; AlphaFold3 predicts nanobody A2's CDR3 adopts an alpha helix rather than the canonical loop. And the univariate analysis: every individual metric fails to separate binders from non-binders (p > 0.05, Mann–Whitney U), while SAGA's composite reaches p = 0.03.

Functional DNA. Designing HepG2-specific enhancers against MPRA-trained predictors, SAGA beats all baselines by 19.2–176.2%; under matched objectives it improves MPRA specificity by ≥48.0% and motif enrichment by ≥47.9%. Designs recover liver-specific transcription-factor motifs and show HepG2-specific CAGE-seq and DNase-seq signal under independent predictors never optimized against.

Materials and chemical processes. For rare-earth-free permanent magnets (DFT-validated) SAGA self-imposes thresholds against single-objective runaway and invents composite targets — semi-pilot adds an Elemental Criticality Index in iteration 3, autopilot adds \(K_1/M_s^2\) to trade anisotropy against saturation magnetization. For superhard materials, >90% of proposed crystals contain B/C/N/O and >75% are transition-metal carbides, nitrides or borides, matching the experimental literature. For butanol/water azeotrope separation, an RL agent maximizing purity alone inserts unit operations that do nothing; SAGA adds complexity, capital-cost and material-flow objectives and recovers near-ideal purity far more cheaply.

Ablations, including a negative one. The Implementer's scorers correlate strongly with human implementations on random molecules (high Pearson/Spearman, low MSE) and on the HepG2 predictor. But §S2.3.1 reports that on antibiotics, objectives proposed after iteration 1 do not visibly improve molecule quality, and the three autonomy modes converge to similar objective sets and similar performance. Most of the value arrives in the first outer step.

How it connects

  • CORAL — the exact complement, and the pairing to read. CORAL keeps a hidden, fixed grader and evolves how you search; SAGA keeps the search ordinary and evolves what you score. CORAL's Appendix A names SAGA's problem as its own open frontier: evaluators are often "incomplete, or even fundamentally ambiguous… evaluation may also need to co-evolve with the solutions."
  • Evolving Benchmarks and Environment Generator Dynamics — the same moving-target structure, better disciplined. Evolving Benchmarks keeps a Lean verifier unforgeable and recalibrates via a single anchor so scores across generations stay commensurable; SAGA has no anchoring protocol, only a held-out metric suite it never trains on. Its objectives are LLM-written Python, which is precisely the forgeable verifier the Lean work engineered away.
  • AdaExplore / AdaEvolve / ASI-Evolve / Darwinian Evolver — fixed-objective siblings; SAGA-Opt is roughly what each of them is, and SAGA could wrap any of them as its Optimizer. Darwin Gödel Machine is the mirror image: DGM evolves the agent against a frozen benchmark, SAGA the benchmark against a frozen agent.
  • Rethinking Harness Evolution — SAGA never reports final performance on the score it optimized, which is the right instinct; but it runs no matched-budget control, so the "more search wearing a costume" explanation stays open. AIDE² RSI evidence and Frontis-MA1 measure a different currency: SAGA is the batch's only entry with physical validation.

Critical take

Baseline fit for TTT on code optimization. Compute and token budget: essentially unreported. No token counts, no dollar figures, no wall-clock times, no cost table anywhere in paper or supplementary — a striking omission next to CORAL's $30–60-per-run accounting. The only efficiency claim is domain-specific (2–5× fewer oracle calls than BoltzGen/Germinal), and outer loops run roughly three iterations. With the inner loop differing per task and three LLMs mixed across modules, there is no single budget quantity to match against.

Feedback signal consumed: the richest — and least reproducible — in this batch. Scalar scores from agent-written scoring functions; web search during Implementation; ToolUniverse domain tools; human expert feedback in two of three modes; and, for the headline claims, wet-lab assays outside the loop. SAGA's most-cited results are therefore not autonomous, though the paper is honest that autopilot merely "achieves comparable performance."

Code availability: MIT-licensed at btyu/SAGA, with the four modules and domain-agnostic scorer/analysis/planning machinery. But the repo documents experiment scripts for DNA sequence design and drug design only — no nanobody, materials, or chemical-process modules, i.e. exactly the tasks behind the wet-lab claims. Setup demands Linux + GPU + Docker + Claude Code CLI, and the README warns other configurations are "not guaranteed to work." Reproducibility here is meaningfully below CORAL's.

What a fair matched-budget comparison requires. The moving objective breaks the usual protocol, so the burden is higher, not lower. Adapting the Rethinking Harness Evolution critique: (1) all scores must be reported on the frozen held-out suite, which SAGA does — its best methodological choice; (2) there must be a budget-matched SAGA-Opt — the same optimizer given the compute the outer loop consumed, spent on more inner generations or more restarts. This control does not exist. SAGA-Opt appears only at nominally equal inner-loop settings, so "objective evolution helps" and "the full system simply searched more, with LLM calls the ablation lacks" are not distinguished; (3) a repeated-sampling control — draw \(K\) independent SAGA-Opt runs under randomly perturbed objective weights and take the best on held-out metrics — would test whether objective evolution beats objective diversity; (4) variance: only the DNA task reports scaled standard error over independent runs, and n=1 wet-lab campaigns cannot bound anything.

Other reservations. The autopilot mode's objectives converge to the same short list across modes and replicates (88.8% "statistically driven" on DNA), and §S2.3.1 concedes post-iteration-1 objectives add little — consistent with the deflationary reading that SAGA is mostly an automated first-pass checklist of standard medicinal-chemistry and materials filters, applied faster than a human would. Compound 8's MIC of 128 µg/mL is a weak hit by clinical standards, which the authors acknowledge; three binders at 300–400 nM is a real but modest result. Finally, the supplementary describes the antibiotic setup as "targeting on Klebsiella pneumonia" while every other mention says E. coli — a documentation slip, not a data problem, but a reminder to read the released configs before trusting the setup description.

If you remember three things

  • SAGA's unit of evolution is the objective, not the policy or the program: an outer LLM loop diagnoses failure modes, proposes new objectives, and compiles them into Dockerized MCP scoring functions the inner optimizer then maximizes — with a final selector re-ranking every candidate from every iteration so early discoveries survive abandoned objectives.
  • The single most transferable finding is the nanobody result: no individual in-silico metric distinguished binders from non-binders (p > 0.05), while the composite the agent wrote did (p = 0.03). Automated objective design produced a better surrogate than the field's hand-curated ones — which is a scientific claim, not a benchmark claim.
  • As a TTT baseline it is the odd one out and should be used as a diagnostic, not a competitor: it is the strongest evidence that fixed proxies get exploited (SAGA-Opt over-optimizes activity and drug-likeness collapses), while its own evaluation lacks the compute-matched SAGA-Opt control that would separate "better objective" from "more search," reports no token or cost budget at all, and ships code for only two of its five domains.
