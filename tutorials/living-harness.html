Living-Harness: Post-Episode Harness Evolution via Episodic Memory + State Graphs

9 min read · arXiv:2607.26598 · arXiv · GitHub · X post · Self-Improving Agents & Harnesses

TL;DR

  • "Living-Harness Is an Interactive-Agent Evolver" (arXiv 2607.26598; Yuetian Du, Yucheng Wang, He Xu, Jiexu Xu, Shanwen Tan, Bing Zhao, Boyu Yang, Zhijie Xu, Ming Kong, Hu Wei, Jie Liu, Qiang Zhu) makes the harness the object of self-improvement: after each evaluated episode, a fixed domain-level Evolution-SOP converts the trajectory + evaluator signals into posterior evidence and commits bounded updates to two persistent stores — episodic memory (trigger conditions, failure patterns, recovery actions) and a state graph (state nodes, repair edges, transition rules) — while tools, base context, and model weights stay frozen.
  • With GPT-5.2-medium as the actor, it reaches 83.09 average Pass@1 on τ²-Bench (+10.07pp over Reflexion, the strongest interactive baseline, and above Gemini 3 Pro's 82.92) and 65.50 on MultiWOZ-2.4 (+9.91pp over ReasoningBank). The evolved state transfers retrieval-only: frozen, it improves every reported domain for Gemini 3 Pro, GLM-5, Qwen3-max, and Kimi-k2 — e.g. MultiWOZ Taxi from 0.00 to 43–45.
  • The distinctive engineering is the commit discipline: candidate repairs must pass schema, scope, evidence, constraint, and merge gates before touching the persistent state, and evidence from an episode is never available when that episode is scored. Ablating the Evolution-SOP (keeping the memory and graph containers) costs 9.7 points — the win comes from structured, bounded evolution, not from bolting on memory.

Why this matters

The recurring disease of interactive agents is that they recover without learning: Reflexion-style retries fix the current task instance, then the correction evaporates with the episode, and the same tool-call omission reappears next week. The paper's case study is the perfect specimen — the agent repeatedly concludes "this user should be transferred to a human" and repeatedly fails to call transfer_to_human_agents(), because a textual lesson is not an executable repair.

Living-Harness is the most disciplined version of that argument so far. It draws the update boundary tightly — only the harness state evolves; tools, base context, domain rules, and the Evolution-SOP itself are frozen — and it splits procedural knowledge into two complementary representations: memory for why/when a repair applies, a graph for where it changes the workflow. That the resulting state is a model-agnostic artifact (frozen, it lifts four other backbones purely via retrieval, including a stronger one) is the headline evidence that harness-level learning is real capital, not prompt-tuning residue. For the self-improving-harness agenda, this is a concrete existence proof that post-deployment procedural repair can accumulate across episodes without touching weights.

The core idea

Separate fixed execution resources from an evolving procedural state. In domain \(d\) at episode \(n\), the harness is

\[H_{d}^{(n)}=\left(C_{d}^{\mathrm{act}},\psi_{d},S_{d}^{(n)}\right),\qquad S_{d}^{(n)}=\left(\mathcal{R}_{d}^{(n)},G_{d}^{(n)}\right),\]

where \(C_{d}^{\mathrm{act}}\) is the frozen actor context (tools, base context, domain rules), \(\psi_{d}\) is the frozen domain-level Evolution-SOP governing post-episode updates, and the evolving state \(S_{d}^{(n)}\) is episodic memory \(\mathcal{R}\) plus state graph \(G\). Initialization is empty memory and a coarse graph scaffold, \(S_{d}^{(0)}=(\emptyset, G_{d,\mathrm{scaf}})\) — all fine-grained repairs are induced from evaluated experience.

Figure 1 from the paper: a static harness is fixed after deployment; Living-Harness evolves exactly two components — episodic memory (trigger conditions, failure patterns, recovery actions) and the state graph (state nodes, repair edges, transition rules) — under Evolution-SOP guidance.

After an episode terminates and an evaluator emits signals \(y_n\), the Evolution-SOP runs a posterior–extract–commit pipeline. First an episode abstraction isolates the reusable procedural content (objective, verified facts, outcome, the critical failure/recovery point), then it is split into evidence for each store:

\[e_{n}=\operatorname{Post}_{M,\psi_{d}}\left(x_{n},\tau_{n},y_{n},C_{d}^{\mathrm{act}}\right),\qquad u_{n}=\left(u_{n}^{\mathcal{R}},u_{n}^{G}\right)=\operatorname{Extract}_{\psi_{d}}(e_{n}),\]

where \(x_n\) is the task, \(\tau_n\) the completed trajectory, \(u_n^{\mathcal{R}}\) the memory evidence (trigger/failure/recovery) and \(u_n^{G}\) the graph evidence (states, actions, transitions). Extracted evidence is only a candidate repair — it must survive gating before it becomes persistent state.

The framing contribution is a program-state POMDP view: augment the environment state with an episode-level program state \(z^{(n)}\) induced by \(S^{(n)}\), constant within an episode and changed only by post-episode updates. Proposition 1 shows retrieved procedural context provably tightens the Bayes error bound on execution-relevant latents:

\[\mathcal{B}(\mathcal{I}_{s,z})=\mathcal{B}(\mathcal{I}_{s})-\Gamma_{z}\leq\mathcal{B}(\mathcal{I}_{s}),\qquad \Gamma_{z}=\mathbb{E}\!\left[\operatorname{Var}\!\left(\mathbb{E}[\xi\mid\mathcal{I}_{s,z}]\mid\mathcal{I}_{s}\right)\right]\geq 0,\]

where \(\mathcal{I}_{s}=\sigma(h_t)\) is the interaction-history information set, \(\mathcal{I}_{s,z}\) additionally conditions on the program state, \(\xi\) is an execution-relevant latent, and \(\mathcal{B}(\mathcal{I})=\mathbb{E}[\operatorname{Var}(\xi\mid\mathcal{I})]\) is the Bayes error bound. An approximate version adds an extraction-error term \(\epsilon_z\): the harness helps iff the information gain exceeds the noise introduced by extracting and using it — which is exactly what the commit gates are for.

How it works

Figure 2 from the paper: the rollout–evaluate–update loop. Memory and state graph evolve (flame icons); tools and context are frozen (snowflake icons). Over cycles the state goes from sparse/incomplete to structured/well-connected.

Each episode runs retrieve → act → evaluate → update. Retrieval builds a task-conditioned query \(q_n = Q(x_n, f_n)\) from the task and its family scope, pulls top-\(k{=}3\) entries from each store (same-family-first, ranked by semantic relevance, family compatibility, and accumulated confidence), and renders them as actor-facing context; the rollout then conditions on it:

\[\kappa_{n}=\operatorname{Render}\!\left(\operatorname{Retrieve}_{\mathcal{R}}(\mathcal{R}^{(n)},q_{n}),\operatorname{Retrieve}_{G}(G^{(n)},q_{n})\right),\qquad \tau_{n}\sim p_{M}\!\left(\tau\mid x_{n},C_{d}^{\mathrm{act}},\kappa_{n}\right),\]

with the fixed rules in \(C_d^{\mathrm{act}}\) always taking precedence over retrieved content. The state is frozen for the whole rollout; accepted evidence lands only in \(S^{(n+1)}=\operatorname{Update}_{\psi_{d}}\left(S^{(n)},u_{n};C_{d}^{\mathrm{act}}\right)\).

Loop over episodes n = 0, 1, 2, ... in domain d:
  1  q_n ← Q(x_n, f_n)                          # task-conditioned query, family scope f_n
  2  κ_n ← Render(top-3 from R^(n), top-3 from G^(n))   # same-family-first retrieval
  3  τ_n ← rollout under frozen tools/context C_d + κ_n
     (task-local reflexion ≤ 3 trials allowed; its buffer is NEVER written to R or G)
  4  y_n ← Evaluator(x_n, τ_n)                  # score BEFORE any update (no same-episode reuse)
  5  e_n ← Post(x_n, τ_n, y_n, C_d)             # episode abstraction via Evolution-SOP ψ_d
  6  (u_R, u_G) ← Extract_ψd(e_n)               # candidate repair, schema-constrained JSON
  7  gate the candidate:
       schema gate     — valid memory/graph schema (one repair pass, then discard)
       scope gate      — committed to its task family unless transfer is supported
       evidence gate   — grounded in evaluator feedback / trajectory / repeated failure
       constraint gate — must not override frozen policies or tool preconditions
       merge gate      — near-duplicates merged via semantic hash + confidence, not inserted
  8  if accepted: R^(n+1), G^(n+1) ← write/strengthen entries and repair edges
     else:        S^(n+1) ← S^(n)

Two details matter for trusting the numbers. First, the score-before-update protocol: evidence generated by an episode is never available when computing that episode's reported score (MultiWOZ syncs updates every four scored episodes). Second, task-local reflection (up to 3 trials) is quarantined from the global state — persistent evolution only ingests evaluator-grounded evidence. The Evolution-SOPs are run-frozen, per-domain documents (8 of them, reproduced in the appendix) specifying how failures are interpreted and what is eligible for commitment; the posterior–extract–commit machinery is shared across domains.

Results

On τ²-Bench (Retail/Airline/Telecom) with GPT-5.2-medium, Living-Harness averages 83.09 Pass@1 vs. 73.02 for Reflexion (best interactive baseline; +10.07pp) and 82.92 for Gemini 3 Pro, the best flagship. Per-domain: 85.96 Retail, 88.00 Airline, 78.07 Telecom. On MultiWOZ-2.4 it averages 65.50 vs. 55.59 for ReasoningBank (+9.91pp) and 53.10 for Reflexion; slightly below Reflexion on 1-domain tasks but best on the 2- and 3-domain groups — repairs pay off most when procedures compose across domains. AWM and EvoTest trail well behind.

Evolution dynamics (Table 2): Retail climbs 57.02 → 85.96 and Telecom 57.39 → 78.07 over three cycles; MultiWOZ final-cycle gains are +13.96 to +28.71 per domain. The biggest jumps come after cycle 1 with smaller refinements later — consistent with "repair the missing workflow steps first, then polish." State growth is roughly linear (Retail: 198 memory entries, 714 nodes / 1,368 edges after cycle 3).

Ablations: removing the Evolution-SOP (generic extractor, no commit gates or family scoping, containers kept) drops the τ²-Bench average from 83.09 to 73.38 — the largest hit; w/o memory 77.34, w/o state graph 79.50, so the two stores are complementary. The transfer result is the one I find most consequential: the GPT-5.2-evolved state, frozen and used retrieval-only, improves every MultiWOZ domain for all four other backbones — GLM-5/Qwen3-max/Kimi-k2 go from 0.00 to 43.08/45.13/45.13 on Taxi, and even Gemini 3 Pro gains (e.g. Taxi 30.26 → 68.72).

How it connects

  • Recursive Harness Self-Improvement — the maximalist version: the harness edits itself, including the machinery that edits. Living-Harness deliberately stops short — the Evolution-SOP is frozen, so the improver never becomes the improved.
  • EvoHarness-RL — trains harness usage into the weights via RL; Living-Harness is the complementary weights-frozen path where all learning lives in retrievable state.
  • Harness Handbook — argues for readable/editable harnesses; Living-Harness's schema-constrained JSON memories and explicit repair edges are what "editable" looks like when the editor is an evaluated pipeline rather than a human.
  • MSCE: Memory into Executable Skills — same diagnosis (textual lessons don't execute), different artifact: MSCE compiles memory into skills, Living-Harness into state-conditioned repair edges next to the memory that justifies them.
  • Agentic Context Management — the retrieval-and-render step here (top-3, same-family-first, fixed rules take precedence) is a concrete context-management policy for procedural knowledge.
  • It also reads as a working instance of scaffold-level (L2) evolution with evidence-gated commits in the sense of the Reliable Self-Evolving Agents survey added today — including honest compliance with "score before update."

Critical take

The commit gates reduce noise ingestion but there is no rollback or regression testing (the authors say so): a plausible-but-wrong repair that passes the evidence gate persists and gets retrieved forever, and nothing in the loop re-audits old entries when the environment or policy changes. Per-cycle "occasional mild fluctuations" hint this is not hypothetical. Second, the Evolution-SOPs are hand-written per domain — eight bespoke documents for eight environments, a real authoring cost and a hidden prior; the ablation shows this is where much of the gain lives, so "self-evolving" is doing less work than "well-specified evolution protocol." Third, the state graph's edge count grows linearly without pruning (+456 edges/cycle in Retail), which retrieval top-3 masks at this scale but won't at 100 cycles. Finally, everything depends on post-episode evaluator signals — benchmarks provide them; most deployments don't. And the POMDP theory holds only when information gain beats extraction error — the regime the gates try to buy but cannot guarantee.

If you remember three things

  1. Bounded target: only \(S=(\mathcal{R},G)\) evolves — trigger/failure/recovery memories plus state-graph repair edges — under a frozen Evolution-SOP, frozen tools/context, frozen weights; candidates pass schema/scope/evidence/constraint/merge gates, and episodes are scored before their evidence can be committed.
  2. It beats the strongest interactive baselines by ~10pp Pass@1 on both τ²-Bench (83.09) and MultiWOZ-2.4 (65.50), with the SOP ablation (−9.7) showing structured bounded evolution — not memory per se — is the active ingredient.
  3. The evolved harness state is portable capital: frozen and reused retrieval-only, it improves four other backbones on every reported domain, taking some 0.00 scores to ~45.
