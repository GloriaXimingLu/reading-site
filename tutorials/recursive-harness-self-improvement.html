Recursive Harness Self-Improvement (Sakana/Berkeley)

10 min read · arXiv:2607.15524 · arXiv · X post · Self-Improving Agents & Harnesses

TL;DR

  • Recursive Harness Self-Improvement (RHI) (Lee, Xu, Seely, Lee, Zaharia, Tang — Sakana AI & UC Berkeley, arXiv 2607.15524) represents the agent harness as a prompt-level specification of the agent loop and iteratively refines that specification using pairwise feedback over its own revision history — no gradient updates, no code edits to a provider scaffold.
  • On 30 synthetic ML-research tasks (quantitative finance, robotics, pharmacy), a few RHI iterations raise the performance ceiling of low-reasoning-effort agents above the maximum-reasoning-effort setting of the same model, while cutting inference cost by up to 60%.
  • The mechanism, per the authors' analysis, is not longer reasoning traces but better task-specific context management — more effective inter-agent information flow — which they formalize as an information-theoretic hypothesis about RHI's implicit objective.

Why this matters

The dominant framing of harnesses (Claude Code, Codex, and their open clones) has been inference-time scaffolding: prompts, tools, and control flow wrapped around a frozen model. This paper adopts the newer model–harness co-evolution view: harnesses are also data-generating components, because their execution traces feed the training corpora of future foundation models. Under that view, a harness has two objectives — immediate task performance and the quality of the traces it emits for future training. The authors explicitly position RHI as addressing "the first half of the model–harness coevolution loop" (the harness-optimization half; the model-training half is what OpenForgeRL-style work addresses — see below).

The practical gap RHI fills: provider-built scaffolds are expensive and labor-intensive to update continually, and most users cannot modify them anyway. So the question becomes whether user-constructed, task-specific harnesses can be optimized cheaply — computationally lightweight, only a few update iterations — while still improving trace quality. That is a much more accessible regime than end-to-end RL on the model, and it is complementary to it.

This sits inside a fast-moving 2026 thread in this reading list: the Harness Handbook makes hand-editing harness code tractable; the harness-generalization paper shows no fixed harness wins across model–problem pairs (so per-task adaptation is not optional, it is forced); the long-horizon-agents survey frames the whole area as Harness × Optimization co-evolution. RHI is the "optimize the harness automatically, per task, at inference time" corner of that space.

The core idea

The single key insight: if the harness is expressed as text, harness optimization becomes a text-refinement problem the model can do to itself. RHI represents the whole agent loop — roles, hand-offs, what each sub-agent sees, how information flows between them — as a prompt-level specification. Improvement is then recursive: run the harness, gather pairwise comparisons between the current revision and earlier revisions in its own history, and use that feedback to write the next revision. The optimization signal is relative (this revision beats that one), which avoids needing calibrated absolute scores of harness quality — notoriously noisy in this setting.

Figure from the paper: Recursive Harness Self-Improvement. At iteration \(i\) the agent solves the task with harness \(H^{(i)}\); an LLM evaluator compares output[i] with output[i-1]; the preference is stored in the self-comparison history; an LLM harness optimizer updates \(H^{(i)} \to H^{(i+1)}\).

The second, less obvious part of the idea is what gets optimized in practice. The authors argue the gains arise primarily from improved task-specific context management — the revisions restructure which information reaches which component of the loop — rather than from eliciting longer chains of thought. They elevate this to an information-theoretic hypothesis about RHI's implicit optimization objective: roughly, RHI is doing continual learning by reshaping the harness's internal information channels (the precise formalization is in the paper; the abstract states the claim but not the functional form).

How it works

From the abstract and thread, the pipeline is:

  1. Harness-as-prompt. Author the agent loop as a prompt-level specification. This is a user-constructed, task-specific harness — not a fork of a provider scaffold — so it is fully readable and rewritable by an LLM.
  2. Execute. Run the current harness revision on tasks from the target domain, producing execution traces and outcomes.
  3. Pairwise feedback over revision history. Compare the current revision against its predecessors — the feedback signal is pairwise preferences over the harness's own revision history rather than an absolute score. (The exact comparison protocol — which pairs, judged by outcome metrics vs. an LLM judge — is not specified in the abstract; verify in the paper.)
  4. Refine. Generate a revised harness specification conditioned on that feedback; the revision is appended to the history.
  5. Recurse. Repeat for a small number of iterations — the abstract emphasizes that a few iterations suffice, which is what keeps the method computationally lightweight.

The objective and the update rule (from the paper's full text). The ideal harness-optimization objective is the expected pairwise win rate against a reference population of competing harnesses:

\[f_x(H)=\mathbb{E}_{H'\sim\mu,\; y\sim\mathcal{A}(H,x),\; y'\sim\mathcal{A}(H',x)}\big[\mathbf{1}\{\mathcal{L}_{\mathrm{eval}}(y,y';x_{\mathrm{eval}})=y\succ y'\}\big],\qquad H_x^{*}\in\arg\max_{H\in\mathcal{H}} f_x(H)\]

where \(\mathcal{A}(H,x)\) is the coding agent running harness \(H\) on task \(x\), \(y\) is the produced repository, \(\mathcal{L}_{\mathrm{eval}}\) is an LLM judge conditioned on evaluation prompt \(x_{\mathrm{eval}}\), and \(\mu\) is a reference distribution over competitors. Population methods approximate this with \(\Theta(m^2)\) pairwise evaluations per iteration; RHI instead uses a trajectory-local relaxation that compares only against the immediately previous revision:

\[\widetilde f_x^{(i)}(H)=\mathbb{E}_{y\sim\mathcal{A}(H,x),\; y^{-}\sim\mathcal{A}(H_x^{(i-1)},x)}\big[\mathbf{1}\{\mathcal{L}_{\mathrm{eval}}(y,y^{-};x_{\mathrm{eval}})=y\succ y^{-}\}\big]\]

which costs exactly one new agent execution and one pairwise evaluation per iteration (\(\Theta(1)\)); under a Bradley–Terry-style latent-utility model this preserves the same utility ordering, so each comparison is a noisy local ascent signal. Because a single comparison is noisy, updates condition on the whole self-comparison history

\[\mathcal{D}_x^{(i)}=\big\{\mathcal{L}_{\mathrm{eval}}(y_x^{(k)},y_x^{(k-1)};x_{\mathrm{eval}})\big\}_{k=1}^{i},\qquad H_x^{(i+1)}=\mathcal{L}_{\mathrm{harness}}\big(H_x^{(i)},\mathcal{D}_x^{(i)}\big)\]

where \(y_x^{(k)}\) is the output of the \(k\)-th revision and \(\mathcal{L}_{\mathrm{harness}}\) is an LLM harness optimizer that never sees \(x_{\mathrm{eval}}\) directly — the evaluation criteria reach it only implicitly through accumulated preferences.

Algorithm (RHI, condensed from Algorithm 1 in the paper):
Input: tasks {x_j}, agent A, evaluator L_eval, harness optimizer L_harness,
       eval prompt x_eval, stopping threshold eps
Initialize harness H(0) per task; history D <- {}; run A(H(0), x) once
for i = 1, 2, ...:
    for each task x_j:
        y(i) <- A(H(i), x_j)                          # run current harness
        D_j  <- D_j U {L_eval(y(i), y(i-1); x_eval)}  # compare vs. predecessor
    s_i <- (1/n) * #{tasks where y(i) beats y(i-1)}   # improvement rate
    if s_i < eps: break                                # revisions stopped winning
    H(i+1) <- L_harness(H(i), D)                       # rewrite spec from history
return task-specific harnesses H*

The harness itself is decomposed into agent design (roles + instructions) and agent workflow, with the workflow split into contracts (what information each sub-agent returns to the orchestrator) and hops (the interaction structure). RHI prioritizes rewriting contracts and hops — the paper's stated hypothesis is that task-specific contracts act like a learned sparsity pattern on inter-agent information flow (dense shared history ≈ dense attention; a contract ≈ task-specific sparse communication), which is where the context-management gains come from.

Two properties are worth flagging. First, this is hill-climbing in harness-space with the model as the mutation operator, structurally similar to evolutionary prompt/program optimization but with the search object being the entire agent loop, not a single prompt. Second, because the harness is the unit of optimization, improvements persist across tasks in the domain without touching model weights — it is a continual-learning mechanism that lives entirely in the scaffold. (How much cross-task transfer occurs within a domain vs. per-task re-optimization is inferred from the thread — verify in the paper.)

Results

Figure from the paper: few-shot RHI raises the performance plateaus of test-time scaling — across 30 synthetic ML research tasks, high-reasoning agents with RHI-improved harnesses achieve higher pairwise win counts than test-time-scaling baselines (mean over two LLM judges, three seeds).

Numbers actually present in the abstract:

  • Benchmark: 30 synthetic machine-learning research tasks spanning quantitative finance, robotics, and pharmacy.
  • Headline: a few RHI iterations "substantially raise the performance ceiling of low-reasoning-effort agents, exceeding the corresponding maximum-reasoning-effort setting" — i.e., a cheap model configuration plus an optimized harness beats the same model at max reasoning effort with the unoptimized harness.
  • Cost: inference cost reduced by up to 60% relative to the maximum-reasoning-effort setting.
  • Mechanism analysis: gains attributed to improved inter-agent information flow / context management rather than longer reasoning traces (qualitative claim plus the information-theoretic formalization).

No per-task numbers, baselines, or model identities are given in the abstract; do not quote finer-grained figures without reading the paper.

How it connects

  • Training Agents Inside Their Harnesses (OpenForgeRL, this list): the literal other half of the co-evolution loop. OpenForgeRL trains the model inside a fixed real harness via RL; RHI improves the harness around a fixed model. A full co-evolution system would alternate the two, with RHI-style optimization also curating the traces OpenForgeRL-style training consumes.
  • Harness Handbook (this list): attacks the same "harnesses must evolve" problem from the code side — behavior localization in large production harness repos. RHI sidesteps that entirely by keeping the harness in prompt-space, which is exactly why it only applies to user-constructed harnesses, not to Claude Code-scale codebases.
  • No Universally Best Harness (this list): provides the empirical justification for RHI's premise. If harness choice is a model–problem-specific hyperparameter with no universal winner, then per-task harness adaptation (RHI) or online harness selection (their adaptive-allocation experiment) are the two natural responses.
  • Long-Horizon Agents survey (this list): RHI is a clean instance of the survey's "self-evolution" cell in the optimization pillar, and its trace-quality objective matches the survey's claim that harness capabilities get internalized into future models.
  • Also related in this list: AREX (recursively self-improving deep-research agent), evolving-benchmarks (if the harness self-improves, the eval must too), and agentic-context-management (RHI's gains are, per the authors, mostly a context-management story).
  • Well-known prior work: ADAS (Hu et al., 2024) searched over agentic system designs in code with an LLM meta-agent; Sakana's own Darwin Gödel Machine (2025) had agents rewrite their own scaffold code with empirical validation; DSPy and reflective prompt-evolution methods (e.g., GEPA-style pairwise/textual feedback) optimize prompts programmatically. RHI's distinguishing bets are the prompt-level representation of the whole loop, pairwise feedback over revision history, and the trace-quality/co-evolution framing.

Critical take

  • Synthetic tasks. All 30 tasks are synthetic ML-research tasks. Whether RHI's gains survive contact with messy real workloads (real repos, real data, underspecified goals) is untested here.
  • Variance. The harness-generalization paper in this list shows discovery/agent-harness comparisons are extremely high-variance and often under-replicated. The abstract does not say how many seeds/repeats back the "exceeds max-reasoning-effort" claim — check the paper's statistical protocol before leaning on it.
  • Cost accounting. The 60% figure is inference cost; the abstract does not state whether the cost of RHI's own refinement iterations (running comparisons, generating revisions) is amortized into it. For few iterations this is plausibly small, but verify.
  • Trace quality is asserted, not closed-loop tested. The motivation is better training data for future models, but "first half of the loop" means no experiment here shows a model actually trained on RHI-optimized traces improving. That is the load-bearing claim of the co-evolution framing and it remains open.
  • Overfitting to the judge. Pairwise feedback over one's own revision history can drift toward whatever the comparison signal rewards (Goodharting the judge), especially if the judge is an LLM. The information-theoretic hypothesis is a post-hoc explanation, labeled as a hypothesis by the authors themselves.
  • Scope. By construction, RHI applies to prompt-level, user-constructed harnesses. Production harnesses with real code, state machines, and tool infrastructure are out of scope — that is Harness Handbook territory.

If you remember three things

  • RHI = the agent loop written as a prompt, recursively rewritten via pairwise comparisons against its own revision history — harness optimization as self-refinement in text-space.
  • A few iterations let a cheap low-reasoning configuration beat the same model at max reasoning effort, at up to 60% lower inference cost, and the gains come from better context/information flow, not longer thinking.
  • It is explicitly the harness half of model–harness co-evolution: pair it mentally with OpenForgeRL (model half) and the harness-generalization result (why per-task adaptation is necessary at all).
