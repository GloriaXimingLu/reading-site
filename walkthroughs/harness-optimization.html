Harness Optimization

26 min · 33 papers · 2026-08-23

Six dimensions separating systems that automatically modify part of an agent's harness — its prompts, tools, control flow, memory, or the code binding them — using evidence from the agent's own execution. Nine systems are placed on all six in detail, followed by the evaluation audit they are read against and the placement of the remaining systems.

Where a source is silent, the cell says so rather than inferring a value. Statements name the systems they cover; no corpus-wide proportions are asserted, because the corpus boundary is itself a judgement.

D1 · Object — what artifact changes on disk?

  • prompt-level spec — RHI rewrites the text that describes the agent loop: roles, contracts, hops.
  • skill file — OEO commits a new version of a Markdown skill document read into the model's context.
  • memory or context — Living-Harness writes episodic-memory entries and state-graph repair edges.
  • harness code — DGM edits its own Python repository: tools, prompts, control flow.
  • environment — EnvHarness wraps a frozen benchmark with Setup, Rule, and Link components.
  • objective — SAGA compiles new scoring functions and then optimizes against them.
  • model weights — EvoHarness-RL takes gradient steps alongside its skill-store edits.

Granularity varies independently: bounded patch operators (SkillOpt), structured operations such as revise / select / stop (OEO), free-form rewrite (DarwinX), whole-repo agentic edits (DGM), or a gradient step.

D2 · Editor — what performs the edit, and what can it see?

  • single model call — RHI: one LLM call reads the preference history and emits the next specification.
  • reflective call under a fixed procedure — Living-Harness: an extract-then-commit pipeline runs under a hand-written standard operating procedure the model cannot change.
  • agent with tools — Meta-Harness: a coding agent runs grep and cat over a filesystem holding every prior candidate's code, score, and execution traces.
  • trained editor — Harness-R1: a 9B model trained specifically to emit harness patches.
  • gradient update — SPADE: GRPO updates the weights that generate environments.

Bandwidth is the amount of evidence reaching the editor per edit. Meta-Harness reports about 10 MTok per iteration against 0.002–0.026 MTok for prior text optimizers, and ablates it: full traces 50.0, LLM summaries 34.9, scores only 34.6.

D3 · Evidence — what is each edit conditioned on?

  • scalar score — AIDE²: one aggregate private score per candidate.
  • execution traces — Meta-Harness: the raw logs of every prior run, searchable.
  • paired comparison — Mendel GM: two runs chosen to differ in exactly one respect, same agent on two tasks or two lineages on one task.
  • verifier or tests — DGM: the benchmark's own private test patch.
  • LLM judge — RHI: a model ranks the new revision against the previous one.
  • human — SAGA: a person intervenes in two of its three autonomy modes.

Independently of source, feedback is either external or self-generated. Evo-Harness tested a self-generated arm and rejected it: 27.96 against 29.54 for no evolution at all.

D4 · Memory — what persists across edits?

  • none — Harness-R1: every patch starts from the frozen target.
  • linear history — OEO: an ordered list of committed checkpoints it can roll back to.
  • raw archive — DGM: a tree holding the code of every functioning ancestor.
  • compiled artifacts — AdaExplore: 78 distilled validity rules, kept instead of the runs that produced them.
  • shared across agents — CORAL: one attempts / notes / skills filesystem read and written by four concurrent agents.

Separately, rejected edits are either retained (SkillHone keeps a decision history of what was declined) or discarded (DGM leaves no trace of a broken child).

D5 · Search — how are candidates produced and admitted?

Topology:

  • none — Ouroboros: sequential evolution tasks, no candidate set.
  • greedy — Living-Harness: one commit per episode, no alternatives generated.
  • archive — DGM: any functioning ancestor can be sampled as the next parent.
  • population archive — DarwinX: parallel branches that can later be merged.
  • lineage tree — Mendel GM: clade-level Thompson sampling over the tree.
  • Pareto frontier — Meta-Harness: candidates retained on a score–cost frontier.
  • agent-directed — OEO: the optimizer itself decides when to branch, roll back, or stop.

Admission gate:

  • functionality — DGM: the child compiles and can still edit code. No score requirement.
  • strict improvement — HCL: validation score must not decrease.
  • preserve-and-extend — DarwinX: positive gain with regression bounded below a threshold.
  • peer review — SkillHone: an accept / reject / request-changes verdict from a reviewing agent.
  • optimizer-chosen — OEO: no external gate; the optimizer commits and selects its own final checkpoint.

D6 · Recursion — is the editor itself in the edit set?

  • no — Meta-Harness freezes its outer loop by design; only the harness under test changes.
  • partial — DGM edits the repository that does the editing, but parent selection and the diagnosis model stay fixed.
  • yes — Hyperagents makes the meta-level modification procedure itself editable.

Evidence scorecard

D1–D6 describe design. Evidence quality is tracked separately, because a system can be fully specified on D1–D6 and weakly evidenced. Each check is marked ✓ present, ✗ absent or violated, ~ partial, or — where the source does not say.

  • sealed split — evaluation data the optimizer can never touch. OEO scores its final skill once on such a split.
  • held-out tasks — tasks not used during optimization. DGM measures transfer to benchmarks and models it never evolved against.
  • matched-budget control — the same compute spent a simpler way. DGM's greedy ablation removes the archive at equal budget: 39.7 against 50.0.
  • repeated-sampling baseline — the same budget spent on more attempts instead. Meta-Harness compares against Best-of-N.
  • contamination addressed — leakage between optimization and evaluation data is checked. Ouroboros filters SWE-bench Pro reference leakage.

DGM — Darwin Gödel Machine

Field arXiv 2505.22954
D1 Object harness code, whole-repo agentic edits — its own Python repository: tools, prompts, control flow. One feature per child.
D2 Editor agent with tools — the agent rewrites its own repo. Diagnosis comes from a separate frozen model (o1), not the editing agent. Bandwidth not reported.
D3 Evidence verifier or tests, external — one run's logs, the GitHub issue, the predicted patch, and the benchmark's private test patch, read by the diagnosis model.
D4 Memory raw archive — a tree of every functioning ancestor's code. Rejected edits discarded: broken children leave no trace.
D5 Search archive topology — any functioning ancestor can be sampled as parent, ∝ sigmoid(score) × 1/(1+children). Gate: functionality — the child compiles and can still edit code. No score requirement.
D6 Recursion partial — the agent edits the code that does the editing, but parent selection and the diagnosis model stay frozen.
Evidence scorecard sealed split ✗ · held-out ✓ (cross-benchmark, cross-model transfer) · matched-budget ✓ (greedy ablation) · repeated-sampling ✗ · contamination ~ (hard-coding risk flagged, no memorization found on inspection)
Result SWE-bench Verified 20.0% → 50.0%. Ablations: greedy 39.7%, no archive 23.0%, no self-improvement 39.0%. Polyglot search subset 14.0 → 38.0 and full benchmark 14.2 → 30.7, reported separately.
Limit Node 114 scored a perfect 2.0 by deleting the hidden hallucination-detection markers. About $22k and two weeks per run.

Mendel GM

Field arXiv 2608.07645
D1 Object harness code, free-form self-rewrite — agent source plus scaffolding, treated as a genotype. No code splicing between lineages.
D2 Editor agent with tools — the target agent edits its own code. Evidence budget: two (trajectory, outcome) records per edit; a retained clonal operator uses one, at λ = 0.10.
D3 Evidence paired comparison, external — two runs differing in exactly one respect: same agent on two tasks, or two lineages on one task. Binary verifier outcomes.
D4 Memory raw archive — a tree storing code and every recorded phenotype, plus a global failure pool the released configuration neutralises at β_fail = 1.0. Rejected-edit memory not reported.
D5 Search lineage tree — clade-level Thompson sampling with a widening rule N^α ≥ |V|. Gate: validation pass — admits any child that validates.
D6 Recursion partial — the agent rewrites itself; the search machinery is untouched.
Evidence scorecard sealed split ✗ (evolves and reports on the same 60-task subsets) · held-out ✓ (zero-shot cross-benchmark and cross-model) · matched-budget ✓ (budget, seed, backbone) · repeated-sampling ✗ · contamination —
Result Polyglot-60 50.8% → 93.2%, against HGM 77.9% at identical budget.
Limit Headline figures are search-set numbers; single run, no error bars. Appendix F.2 reports 61.7% on SWE-bench Verified-60 where Table 1 reports 78.3%.

Hyperagents

Meta-Harness

Field arXiv 2603.28052
D1 Object harness code — the harness as a single-file executable Python program. The proposer chooses a local edit or a full rewrite.
D2 Editor agent with tools — a coding agent running grep and cat over the filesystem. Bandwidth: about 10 MTok per iteration, median 82 files, against 0.002–0.026 MTok reported for prior text optimizers.
D3 Evidence execution traces, external — search-set scores plus the raw traces of every prior candidate, searchable rather than summarised.

DarwinX

Field arXiv 2608.07545
D1 Object harness code plus skill file — a skill layer (prompts, memory) and a code layer (tools, control flow). Additive single edits.

RHI — Recursive Harness Self-Improvement

Field arXiv 2607.15524
D1 Object prompt-level spec — the text describing the agent loop: roles, contracts, hops. Free-form rewrite of the whole loop.
D2 Editor single model call — one LLM call that sees the preference history only, never the evaluation prompt. Bandwidth not reported.
D3 Evidence LLM judge, self-generated — pairwise preference against the immediately previous revision.
D4 Memory linear history — the preference record over a single lineage. Rejected-edit memory not reported.
D5 Search greedy single-lineage hill-climb. Gate: none — every revision is kept; the loop stops when the improvement rate falls below ε.
D6 Recursion no, despite the name. By the update rule H^(i+1) = L(H^(i), D^(i)) the optimizer is a fixed external model: the recursion runs over revision history, not over the editor.
Evidence scorecard sealed split ✗ · held-out — · matched-budget ✗ · repeated-sampling ✗ · contamination —
Result Inference cost reduced by up to 60% relative to the maximum-reasoning-effort setting, at higher performance. Three seeds, two judges.
Limit All 30 tasks are synthetic; pairwise self-judging admits Goodharting the judge.

Living-Harness

Field arXiv 2607.26598
D1 Object memory and context — episodic-memory entries and a state graph. Bounded, schema-constrained JSON commits; no code is touched.
D2 Editor reflective call under a fixed procedure — an extract-then-commit pipeline running under a frozen, hand-written Evolution-SOP. Sees the full trajectory plus evaluator signals.
D3 Evidence verifier, external — evaluator signals and trajectories, scored before the update is applied.
D4 Memory compiled artifacts — memory entries plus state-graph repair edges, portable across model backbones. Rejected candidates discarded.
D5 Search greedy per-episode commit, no population. Gate: five checks — schema, scope, evidence, constraint, merge. No rollback.
D6 Recursion no — the Evolution-SOP is frozen and hand-written.
Evidence scorecard sealed split ~ (score-before-update: an episode's own evidence is never available when that episode is scored) · held-out ✓ (cross-model transfer) · matched-budget ✗ · repeated-sampling ✗ · contamination —
Result τ²-Bench 83.09 average Pass@1, +10.07 points over the strongest interactive baseline; +9.91 on MultiWOZ-2.4.

OEO — Open-Ended Optimization

Field arXiv 2608.09629
D1 Object skill file — a text artifact; Revise commits a new version. The harness itself is frozen.
D2 Editor agent with tools — emits Inspect / RunTarget / Revise / Select / Stop. Bandwidth: a median 34.3% of the reference target-interaction token budget.
D3 Evidence execution traces plus scalar score, external — optimizer-chosen inspection of data and results, plus RunTarget rollouts scored outside the loop. The sealed split is untouchable.
D4 Memory linear history plus a checkpoint list, with rollback via Select. Rejected-edit memory not reported.
D5 Search agent-directed, no prescribed topology. Gate: optimizer-chosen — no external gate; it commits and self-selects the final checkpoint.
D6 Recursion no — the improvement process is composed online but is not itself an edit target.
Evidence scorecard sealed split ✓ (scored once) · held-out ✓ · matched-budget ✓ (static one-shot control, frozen-protocol capability ladder) · repeated-sampling ✗ · contamination —
Result 7 wins and 1 tie against SkillOpt across 8 benchmark–target settings; 5 of 6 against GEPA. Two of the 14 headline cells are post-hoc OEO-matched checkpoints, excluded from the confirmatory counts.

The evaluation reference

Rethinking the Evaluation of Harness Evolution

An audit, not a system. It runs the matched-budget and repeated-sampling comparisons that the scorecard's third and fourth checks ask for.

Field arXiv 2607.12227
Claim tested That harness-evolution gains come from better harness design rather than from repeated sampling.
Method Matched budget K = 5 against parallel sampling and sequential refinement; 45 / 10 / 34 train / validation / held-out split.
Result Without unit tests, harness evolution averages 67.4 pass@1 against a 68.2 direct-sampling baseline and 72.3 for parallel sampling. With tests, parallel sampling wins pass@1 86.0 against 75.8. Held-out transfer: +1.2, +0.0, average +0.6.
Constructive arm The paper's own harness-scaling method, per-instance adaptation, is the strongest non-parallel approach without tests: 71.8 and 76.0 on Opus.
Conclusion stated Self-evolving harness loops, as evaluated today, are largely covert test-time scaling; most edits memorize fixes rather than distilling strategies.
Limit One benchmark (Terminal-Bench 2.1, limited harness headroom), one method (AHE minus its explore agent), K = 5.

D3 Evidence. Execution traces: Meta-Harness, Ouroboros, Argus, AIDE², Harness-R1 (a compacted failure packet). Paired comparison: Mendel GM. Verifier or tests: DGM, CORAL, Evolving Benchmarks, DarwinX, Evo-Harness (verifier results, unit tests, tool diagnostics). LLM judge: RHI, AutoDesign, HiSME, Ouroboros. Human: SAGA (2 of 3 autonomy modes), Ouroboros (social feedback).

Self-generated feedback is a design choice in DGM's diagnosis step, HarnessCompass's blind and hindsight self-reports, MSCE's governance, SPADE's hint-based regret, and EnvHarness's LLM diagnosis. Evo-Harness tested it as an ablation arm and rejected it: self-generated feedback scored 27.96 against 29.54 for no evolution at all on CL-Bench.

D4 Memory. None: Harness-R1. Linear history: RHI, OEO. Raw archive: DGM, Mendel GM, Hyperagents, Meta-Harness, DarwinX. Compiled artifacts: Living-Harness, MSCE, HiSME, Evo-Harness, ReASearch, Argus. Shared across agents: CORAL, DarwinX.

They are discarded by DGM, Living-Harness, and HCL. Meta-Harness keeps regressions but not smoke-test failures.

D5 Search. Greedy single lineage: RHI, Living-Harness, HCL, Evo-Harness, AutoDesign, Rethinking Self-Evolving Skills. Archive: DGM, Hyperagents. Population archive: DarwinX, Frontis-MA1. Lineage tree: Mendel GM. Pareto frontier: Meta-Harness. Agent-directed: OEO, Ouroboros, ReASearch, CORAL (which removes the evolutionary algorithm entirely, leaving a heartbeat scheduler and git isolation). Prescribed pipeline: SkillHone.

Admission gates: functionality or compilation — DGM, Hyperagents. Interface smoke test — Meta-Harness. Review quorum with functionality — Ouroboros. Strict improvement — HarnessCompass, HCL, Rethinking Self-Evolving Skills. Preserve-and-extend, meaning positive gain with bounded regression — DarwinX. Validation pass — Mendel GM. Optimizer-chosen — OEO, ReASearch. Peer review — SkillHone.

D6 Recursion. Yes: Ouroboros (excluding launcher and supervisor), Hyperagents (the meta-procedure is editable). Partial: DGM and Mendel GM (the agent edits its own editing code while selection machinery stays frozen), AIDE² (Level 1 candidate evidence, Level 2 ignition explicitly not claimed), SPADE (the designer trains on the solver's response), Frontis-MA1, Argus (verifiers and routing are themselves editable). No: RHI, OEO, Meta-Harness (outer loop frozen by design), SBCO (fixing the meta-agent is its thesis), Living-Harness, HCL, Harness-R1, HarnessCompass, AutoDesign, EnvHarness, Evo-Harness, HiSME, MSCE, SkillHone, CORAL, EvoHarness-RL, Task-CoEvolve, Evolving Benchmarks, SAGA.

Evidence quality across these systems. All five checks are present in Meta-Harness. A sealed split the optimizer cannot touch is reported by Meta-Harness, OEO, HarnessCompass (a 50-task evolution set against 450 held-out), HiSME (150 train, 50 held-out, skills frozen at test), Rethinking Self-Evolving Skills, Harness-R1 (1,270 unseen tasks), AIDE² (public and private score splits), and DarwinX in three of four regimes; SkillHone's redaction firewall and Living-Harness's score-before-update protocol are structural analogues. DGM and Mendel GM evolve and report on the same subsets; DarwinX and Meta-Harness do so within their Terminal-Bench 2.1 and TerminalBench-2 regimes respectively.
