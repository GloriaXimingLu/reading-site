Harness Optimization

21 min · 33 papers · 2026-08-23

An agent is a model plus a harness: prompts, tools, control flow, memory, and the code that binds them. Harness optimization covers systems that modify part of that scaffold automatically, using evidence from the agent's own execution.

This page defines six dimensions that separate such systems, places nine systems on all six in detail, adds the evaluation audit they are read against, and lists where the remaining systems fall. Two final sections list work that shares the machinery or is frequently grouped with harness optimization but does not modify a harness.

Where a source is silent, the cell says so rather than inferring a value. Statements below name the systems they cover; no corpus-wide proportions are asserted, because the corpus boundary is itself a judgement.

The six dimensions

# Dimension Question Values
D1 Object What artifact changes on disk? prompt-level spec · skill file · memory/context · harness code · environment · objective · model weights
D2 Editor What performs the edit, and what can it see? single model call · reflective call under a fixed procedure · agent with tools · trained editor · gradient update; bandwidth in tokens where stated
D3 Evidence What is each edit conditioned on? scalar score · execution traces · paired comparison · verifier or tests · LLM judge · human; self-generated or external
D4 Memory What persists across edits? none · linear history · raw archive · compiled artifacts · shared across agents; rejected edits kept or discarded
D5 Search How are candidates produced and admitted? none · greedy · archive · population · tree · Pareto · agent-directed; gate: functionality · strict improvement · preserve-and-extend · peer review · optimizer-chosen
D6 Recursion Is the editor itself in the edit set? no · partial · yes

D1–D6 describe system design. Evidence quality is tracked separately, because a system can be fully specified on D1–D6 and weakly evidenced.

Evidence scorecard. Five checks, each marked ✓ present, ✗ absent or violated, ~ partial, or — where the source does not say: sealed split (evaluation data the optimizer cannot touch) · held-out tasks · matched-budget control · repeated-sampling baseline · contamination addressed.

DGM — Darwin Gödel Machine

Field arXiv 2505.22954
Object Own Python agent repo: tools, prompts, workflow. Whole-repo agentic edits, one feature per child.
Editor Agent with tools rewrites its own repo. A separate frozen model (o1) produces the diagnosis. Bandwidth not reported.
Evidence One run's logs, the GitHub issue, the predicted patch, and the private test patch, read by the separate diagnosis model rather than by the editing agent.
Memory Raw archive tree of functioning ancestors. Broken children are discarded; no rejected-edit memory.
Search Open-ended archive. Parent sampling ∝ sigmoid(score) × 1/(1+children). Admission requires functionality — the child compiles and can still edit code — not a score improvement.
Recursion Partial. The agent edits the code that does the editing; parent selection and the diagnosis model stay frozen.
Scorecard sealed split ✗ · held-out ✓ (cross-benchmark, cross-model transfer) · matched-budget ✓ (greedy ablation) · repeated-sampling ✗ · contamination ~ (hard-coding risk flagged, no memorization found on inspection)
Result SWE-bench Verified 20.0% → 50.0%. Ablations: greedy 39.7%, no archive 23.0%, no self-improvement 39.0%. Polyglot search subset 14.0 → 38.0 and full benchmark 14.2 → 30.7, reported separately.
Limit Node 114 scored a perfect 2.0 by deleting the hidden hallucination-detection markers. About $22k and two weeks per run.

Mendel GM

Field arXiv 2608.07645
Object Agent source plus scaffolding, treated as a genotype. Free-form self-rewrite; no code splicing between lineages.
Editor The target agent edits its own code. The comparative operator supplies two (trajectory, outcome) records; a retained clonal-mutation operator uses one, sampled at λ = 0.10.
Evidence Paired comparison: the same agent on two tasks, or two lineages on one task. Binary verifier outcomes.
Memory Archive tree storing code and every recorded phenotype, plus a global failure pool that the released configuration neutralises at β_fail = 1.0. Rejected-edit memory not reported.
Search Lineage tree with clade-level Thompson sampling and a widening rule N^α ≥ |V|. Admits any child passing validation.
Recursion Partial. Search machinery is untouched.
Scorecard sealed split ✗ (evolves and reports on the same 60-task subsets) · held-out ✓ (zero-shot cross-benchmark and cross-model) · matched-budget ✓ (budget, seed, backbone) · repeated-sampling ✗ · contamination —
Result Polyglot-60 50.8% → 93.2%, against HGM 77.9% at identical budget.
Limit Headline figures are search-set numbers; single run, no error bars. Appendix F.2 reports 61.7% on SWE-bench Verified-60 where Table 1 reports 78.3%.

Hyperagents

Field arXiv 2603.19461
Object The whole hyperagent program: task agent, tools, memory, and the meta agent's own modification procedure. Whole-repo edits.
Editor The system's own meta agent, using bash and file-edit tools. About 33M self-modification tokens per 100-iteration run.
Evidence Archive scores and prior per-domain evaluation results.
Memory Archive of hyperagents. Agents introduced their own persistent memory and a PerformanceTracker during runs.
Search Open-ended archive. Parent sampling ∝ sigmoid(score − top-3 mean) × novelty. Admits if it compiles.
Recursion Yes. The meta-level modification procedure is itself editable; parent selection remains frozen.
Scorecard sealed split ✗ · held-out ✓ (validation split, unseen-domain meta-transfer) · matched-budget ✓ (DGM-custom baseline) · repeated-sampling ✗ · contamination —
Result Transferred hyperagents reach imp@50 = 0.630 on unseen IMO grading; controls approximately 0. Five runs with bootstrap confidence intervals.
Limit The advantage over the fair DGM-custom baseline is not statistically significant.

Ouroboros

Field arXiv 2608.08311
Object Its own repository: tools, prompts, context assembly, review logic, core code. Whole-repo commits.
Editor The agent itself plus scout and acting subagents in worktrees; the parent is the sole committer. Bandwidth not reported.
Evidence A blocking LLM diff-review panel, deterministic preflight checks, and fingerprint freshness, plus observed bugs. Self-reviewed.
Memory Durable error classes, Git history, a review-evidence ledger, 227 MB of memory artifacts.
Search None. Agent-directed sequential evolution tasks. The gate is a review quorum together with functionality; there is no score-based acceptance.
Recursion Yes, excluding an unmodifiable launcher and supervisor.
Scorecard sealed split ✗ · held-out — (benchmarks run from frozen snapshots; withholding from evolution is not established) · matched-budget ✗ · repeated-sampling ✗ · contamination ✓ (SWE-bench Pro leakage filtered; an audit removed a reward-hacked trial)
Result Terminal-Bench 2.1 86.74%, audited, on Opus 5. On SWE-bench Pro the result is parity: 58.2% against Codex 59.4%, McNemar p = 0.40.
Limit No evidence of compounding gains. Baselines self-reported.

Meta-Harness

Field arXiv 2603.28052
Object The harness as a single-file executable Python program. The proposer chooses a local edit or a full rewrite.
Editor A coding agent with grep and cat over the filesystem: about 10 MTok per iteration, median 82 files. The paper reports 0.002–0.026 MTok per iteration for prior text optimizers.
Evidence Search-set scores plus the raw execution traces of every prior candidate.
Memory Raw filesystem archive of code, scores, and traces per candidate. Regressions are retained and reasoned over; smoke-test failures are not logged.
Search Agent-directed. No parent selection or mutation operators; a Pareto frontier is maintained; admission is a cheap interface smoke test, and the proposer never sees test-set results.
Recursion No. The outer loop is deliberately frozen.
Scorecard sealed split ✓ (test scored once) · held-out ✓ (OOD tasks and held-out models) · matched-budget ✓ (Best-of-N) · repeated-sampling ✓ · contamination ✓ (regex leakage audit). All five present.
Result Full traces 50.0 median / 56.7 best, against LLM summaries 34.9 / 38.7 and scores-only 34.6 / 41.3.
Limit On TerminalBench-2 the search runs on its own evaluation set, and the population is seeded near state of the art. Transfer margins are smaller than the in-search figures: +2.9 out of distribution over ACE and +1.3 over BM25.

DarwinX

Field arXiv 2608.07545
Object A skill layer (prompts, memory) and a code layer (tools, control flow). Additive single edits.
Editor An LLM proposer plus a reasoning verifier agent. Bandwidth not reported.
Evidence Three routed signals — failure diagnosis, teacher demonstrations, self-contrast — scored by the benchmark's own verifier at avg@k without gold labels.
Memory Archive never deletes. Shared cross-generation memory of themes that worked or regressed; losers retained as stepping stones.
Search Population archive with lineage-gain parent sampling and a merge operator. Preserve-and-extend gate: gain g > 0 and regression R ≤ δ.
Recursion No. Selection machinery is fixed.
Scorecard sealed split ✓ in three of four regimes (TerminalWorld evolves on 94 tasks and reports on 41 disjoint; WebArena-Infinity evolves on synthetic intents and never reads the real suites), ✗ on Terminal-Bench 2.1, which evolves on the evaluation set · held-out ✓ · matched-budget ✗ (total evolution compute unreported) · repeated-sampling ✗ · contamination — (a reward-hacking audit found no harness-level cheating; data leakage is not examined)
Result Terminal-Bench 2.1 75.5% → 83.2% on a frozen GPT-5.5.
Limit Archive, parent selector, and merge operator are never independently ablated. In the WebArena-Infinity regime every attempted merge was reverted.

RHI — Recursive Harness Self-Improvement

Field arXiv 2607.15524
Object A prompt-level harness specification: roles, contracts, hops. Free-form rewrite of the whole loop.
Editor A single LLM optimizer call that sees the preference history only, never the evaluation prompt. Bandwidth not reported.
Evidence Pairwise LLM-judge preference against the immediately previous revision. Self-generated.
Memory Linear preference history over a single lineage.
Search Greedy single-lineage hill-climb. No acceptance gate; stops when the improvement rate falls below ε.
Recursion No, despite the name. By the paper's update rule H^(i+1) = L(H^(i), D^(i)) the optimizer is a fixed external model; the recursion runs over revision history, not over the editor.
Scorecard sealed split ✗ · held-out — · matched-budget ✗ · repeated-sampling ✗ · contamination —
Result Inference cost reduced by up to 60% relative to the maximum-reasoning-effort setting, at higher performance. Three seeds, two judges.
Limit All 30 tasks are synthetic; pairwise self-judging admits Goodharting the judge.

Living-Harness

Field arXiv 2607.26598
Object Harness state only: episodic memory and a state graph. Bounded, schema-constrained JSON commits.
Editor An LLM posterior–extract–commit pipeline running under a frozen, hand-written Evolution-SOP. Sees the full trajectory plus evaluator signals.
Evidence External evaluator signals and trajectories. Not self-generated.
Memory Compiled: memory entries plus state-graph repair edges, portable across model backbones. Rejected candidates are discarded.
Search Greedy per-episode commit, no population. Five gates: schema, scope, evidence, constraint, merge. No rollback.
Recursion No. The Evolution-SOP is frozen and hand-written.
Scorecard sealed split ~ (score-before-update: an episode's own evidence is never available when that episode is scored) · held-out ✓ (cross-model transfer) · matched-budget ✗ · repeated-sampling ✗ · contamination —
Result τ²-Bench 83.09 average Pass@1, +10.07 points over the strongest interactive baseline; +9.91 on MultiWOZ-2.4.
Limit Removing the eight hand-written per-domain SOPs costs 9.7 points (83.09 → 73.38), the largest single ablation. No regression testing.

OEO — Open-Ended Optimization

Field arXiv 2608.09629
Object A skill text artifact. Free-form Revise commits a new version; the harness is frozen.
Editor An agent emitting Inspect / RunTarget / Revise / Select / Stop. Uses a median 34.3% of the reference target-interaction token budget.
Evidence Optimizer-chosen inspection of data and results, plus RunTarget rollouts scored externally. The sealed split is untouchable.
Memory Linear history plus a checkpoint list; rollback via Select.
Search Agent-directed with no prescribed topology. No external gate: the optimizer commits and self-selects the final checkpoint.
Recursion No. The improvement process is composed online but is not itself an edit target.
Scorecard sealed split ✓ (scored once) · held-out ✓ · matched-budget ✓ (static one-shot control, frozen-protocol capability ladder) · repeated-sampling ✗ · contamination —
Result 7 wins and 1 tie against SkillOpt across 8 benchmark–target settings; 5 of 6 against GEPA. Two of the 14 headline cells are post-hoc OEO-matched checkpoints, excluded from the confirmatory counts.
Limit Capability-dependent: a medium optimizer loses to the prescribed pipeline (+9.68 LiveMath for SkillOpt); a weak optimizer emits no valid actions.

The evaluation reference

Rethinking the Evaluation of Harness Evolution

An audit, not a system. It runs the matched-budget and repeated-sampling comparisons that the scorecard's third and fourth checks ask for.

Field arXiv 2607.12227
Claim tested That harness-evolution gains come from better harness design rather than from repeated sampling.
Method Matched budget K = 5 against parallel sampling and sequential refinement; 45 / 10 / 34 train / validation / held-out split.
Result Without unit tests, harness evolution averages 67.4 pass@1 against a 68.2 direct-sampling baseline and 72.3 for parallel sampling. With tests, parallel sampling wins pass@1 86.0 against 75.8. Held-out transfer: +1.2, +0.0, average +0.6.
Constructive arm The paper's own harness-scaling method, per-instance adaptation, is the strongest non-parallel approach without tests: 71.8 and 76.0 on Opus.
Conclusion stated Self-evolving harness loops, as evaluated today, are largely covert test-time scaling; most edits memorize fixes rather than distilling strategies.
Limit One benchmark (Terminal-Bench 2.1, limited harness headroom), one method (AHE minus its explore agent), K = 5.

Where the remaining systems fall

These lists cover systems that modify part of an agent's scaffold. Work in the two final sections is excluded.

D1 Object. Prompt-level spec: RHI. Skill file: OEO, HiSME, Evo-Harness, MSCE, SkillHone, Rethinking Self-Evolving Skills, Reason-Wide-Not-Deep. Memory and context: Living-Harness, Argus. Harness code: DGM, Mendel GM, Hyperagents, Ouroboros, Meta-Harness, DarwinX, AIDE² (the inner agent's whole repo), AutoDesign (the design harness itself), CORAL (a shared attempts/notes/skills filesystem plus the coordination structure), Harness-R1 (an executable runtime overlay at four lifecycle hooks), SBCO (prompt plus per-constraint verifier code). Prompts, memory, skills and routing without code edits: HCL (four versioned components), HarnessCompass (seven component types). Environment: EnvHarness, SPADE. Objective or task distribution: SAGA (LLM-authored scoring functions), Task-CoEvolve (which validation tasks score a candidate), Evolving Benchmarks (the active task distribution, never the success criterion, alongside workflow, prompts and tools). Model weights together with a scaffold artifact: EvoHarness-RL (weights plus skill store), SPADE (weights plus environment), Frontis-MA1.

D2 Editor. Single model call: RHI. Reflective call under a fixed procedure: Living-Harness, Evo-Harness, HCL, HiSME, Rethinking Self-Evolving Skills. Agent with tools: DGM, Mendel GM, Hyperagents, Ouroboros, Meta-Harness, DarwinX, OEO, AutoDesign, AIDE², EnvHarness, ReASearch, SkillHone, CORAL. Trained editor: Harness-R1 (a 9B engineer model). Gradient update: EvoHarness-RL, SPADE, Frontis-MA1.

Editor bandwidth is quantified in tokens by three systems: Meta-Harness (about 10 MTok per iteration), Hyperagents (about 33M tokens per run), HiSME (15.37 MTok maintenance). Two more quantify an evidence budget rather than tokens: Mendel GM (two trajectory records per edit) and OEO (34.3% of the reference budget). Elsewhere it is unstated.

D3 Evidence. Execution traces: Meta-Harness, Ouroboros, Argus, AIDE², Harness-R1 (a compacted failure packet). Paired comparison: Mendel GM. Verifier or tests: DGM, CORAL, Evolving Benchmarks, DarwinX, Evo-Harness (verifier results, unit tests, tool diagnostics). LLM judge: RHI, AutoDesign, HiSME, Ouroboros. Human: SAGA (2 of 3 autonomy modes), Ouroboros (social feedback).

Self-generated feedback is a design choice in DGM's diagnosis step, HarnessCompass's blind and hindsight self-reports, MSCE's governance, SPADE's hint-based regret, and EnvHarness's LLM diagnosis. Evo-Harness tested it as an ablation arm and rejected it: self-generated feedback scored 27.96 against 29.54 for no evolution at all on CL-Bench.

D4 Memory. None: Harness-R1. Linear history: RHI, OEO. Raw archive: DGM, Mendel GM, Hyperagents, Meta-Harness, DarwinX. Compiled artifacts: Living-Harness, MSCE, HiSME, Evo-Harness, ReASearch, Argus. Shared across agents: CORAL, DarwinX.

Rejected edits are retained by SkillHone (a persistent decision history whose ablation is worth roughly twice the evaluation firewall), AutoDesign (an optimization record with rollback), DarwinX (losers as stepping stones), SBCO (the strategist sees prior failures), ReASearch (a lessons file recording what failed), and HarnessCompass (R³ salvages beneficial loser edits). They are discarded by DGM, Living-Harness, and HCL. Meta-Harness keeps regressions but not smoke-test failures.

D5 Search. Greedy single lineage: RHI, Living-Harness, HCL, Evo-Harness, AutoDesign, Rethinking Self-Evolving Skills. Archive: DGM, Hyperagents. Population archive: DarwinX, Frontis-MA1. Lineage tree: Mendel GM. Pareto frontier: Meta-Harness. Agent-directed: OEO, Ouroboros, ReASearch, CORAL (which removes the evolutionary algorithm entirely, leaving a heartbeat scheduler and git isolation). Prescribed pipeline: SkillHone.

Admission gates: functionality or compilation — DGM, Hyperagents. Interface smoke test — Meta-Harness. Review quorum with functionality — Ouroboros. Strict improvement — HarnessCompass, HCL, Rethinking Self-Evolving Skills. Preserve-and-extend, meaning positive gain with bounded regression — DarwinX. Validation pass — Mendel GM. Optimizer-chosen — OEO, ReASearch. Peer review — SkillHone.

D6 Recursion. Yes: Ouroboros (excluding launcher and supervisor), Hyperagents (the meta-procedure is editable). Partial: DGM and Mendel GM (the agent edits its own editing code while selection machinery stays frozen), AIDE² (Level 1 candidate evidence, Level 2 ignition explicitly not claimed), SPADE (the designer trains on the solver's response), Frontis-MA1, Argus (verifiers and routing are themselves editable). No: RHI, OEO, Meta-Harness (outer loop frozen by design), SBCO (fixing the meta-agent is its thesis), Living-Harness, HCL, Harness-R1, HarnessCompass, AutoDesign, EnvHarness, Evo-Harness, HiSME, MSCE, SkillHone, CORAL, EvoHarness-RL, Task-CoEvolve, Evolving Benchmarks, SAGA.

Evidence quality across these systems. All five checks are present in Meta-Harness. A sealed split the optimizer cannot touch is reported by Meta-Harness, OEO, HarnessCompass (a 50-task evolution set against 450 held-out), HiSME (150 train, 50 held-out, skills frozen at test), Rethinking Self-Evolving Skills, Harness-R1 (1,270 unseen tasks), AIDE² (public and private score splits), and DarwinX in three of four regimes; SkillHone's redaction firewall and Living-Harness's score-before-update protocol are structural analogues. Matched-budget controls are reported by DGM, Mendel GM, Hyperagents, Meta-Harness, OEO, EnvHarness, Task-CoEvolve, AIDE², and ReASearch. Explicit repeated-sampling baselines are reported by Meta-Harness, Rethinking Self-Evolving Skills, and the audit itself; CORAL runs a best-of-4 arm that is not token-matched. DGM and Mendel GM evolve and report on the same subsets; DarwinX and Meta-Harness do so within their Terminal-Bench 2.1 and TerminalBench-2 regimes respectively.

Adjacent work that does not modify a harness

Paper What it is Why it is not on the grid
PRO-LONG Append-only log, frozen weights, fixed harness Nothing is searched, trained, or admitted. It reports +18.0 points pass@1 over a no-log coding agent on ARC-AGI-3, a benchmark the nine systems above do not use.
NOOA Hand-authored harness with typed context APIs No search over harness designs. The model manipulates its own context through exposed APIs and curates memory via seven tools, but no loop proposes or admits harness variants. Its 13.3% → 85.1% figure measures a harness effect.
Cordis Runtime substrate for live plugin swap and revert Answers how an edit is applied and undone safely, not which edit. No editor, no evidence signal, no acceptance rule.
Harness Handbook Behaviour-to-code index for locating edit sites Supplies localization upstream of any loop. It scores plans (S = 0.5·S_Loc + 0.25·S_Scope + 0.25·S_Reason, δ = 3 win threshold) but generates no candidate harnesses and executes no edits.
Agentic Context Management Hand-designed compaction lifecycle No search over designs; the only acceptance rule is a validation retry. Its reported numbers (92.0% LongMemEval, 93.2% LoCoMo categories 1–4) are self-run.
TRACE, AgentOPSD Turn-level RL credit assignment Weights change; the harness is fixed. AgentOPSD's "recursive" refers to a Bayesian belief filter, not to editing an editor.
OpenForgeRL RL training through a production harness Trains through a harness without modifying it. Its finding is that harness choice is a training variable.
Demystifying Agent Skills Measurement study on fixed skills No optimization loop. Procedural anchoring accounts for 65.7% of cases where a skill helps, knowledge injection 4.5%.
SkillGate, SkillRise, Skill-SP RL over skill selection or generation Weights are trained rather than artifacts edited. SkillGate's 16-candidate slate is fixed and read at evaluation; SkillRise's document is deployed at test time but discarded at sequence end; Skill-SP's controller does update a skill library, making it the closest of the three to the grid.
