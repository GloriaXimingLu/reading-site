D1 Object What artifact changes on disk?

prompt-level spec
The text describing the agent loop — roles, contracts, hops. RHI rewrites it wholesale.
skill file
A Markdown document loaded into the model's context. OEO commits a new version each round.
memory or context
What the agent carries between episodes. Living-Harness writes memory entries and state-graph repair edges.
harness code
The program itself — tools, prompts, control flow. DGM edits its own Python repository.
environment
The world the agent acts in. EnvHarness wraps a frozen benchmark in Setup, Rule, and Link components.
objective
The definition of success. SAGA writes new scoring functions, then optimizes against them.
model weights
The policy itself. EvoHarness-RL takes gradient steps alongside its skill-store edits.

D2 Editor What performs the edit, and how much can it see?

single model call
One prompt in, one revision out. RHI passes only the preference history.
reflective call, fixed procedure
The model fills slots in a pipeline it cannot change. Living-Harness runs extract-then-commit under a hand-written SOP.
agent with tools
The editor can go looking. Meta-Harness greps a filesystem holding every prior candidate's code, score, and traces — about 10 MTok per iteration, against 0.002–0.026 MTok for prior text optimizers.
trained editor
A model trained for the job. Harness-R1 uses a 9B engineer that emits patches.
gradient update
No text edit at all. SPADE moves weights with GRPO.

D3 Evidence What is each edit conditioned on?

scalar score
One number per candidate. AIDE² uses an aggregate private score.
execution traces
The raw logs of what happened. Meta-Harness keeps them searchable rather than summarised.
paired comparison
Two runs differing in exactly one respect. Mendel GM pairs one agent on two tasks, or two lineages on one task.
verifier or tests
A ground-truth check. DGM reads the benchmark's private test patch.
LLM judge
A model rates the change. RHI ranks each revision against the one before it.
human
A person intervenes. SAGA does so in two of its three autonomy modes.

Cutting across all six: the signal is external or self-generated. Evo-Harness tried a self-generated arm and dropped it — 27.96 against 29.54 for no evolution at all.

D4 Memory What persists from one edit to the next?

none
Every edit starts fresh. Harness-R1 patches the frozen target with no record of past patches.
linear history
An ordered list, with rollback. OEO keeps committed checkpoints it can return to.
raw archive
Everything kept, unprocessed. DGM holds the code of every functioning ancestor in a tree.
compiled artifacts
Lessons kept, runs discarded. AdaExplore distils failures into 78 validity rules.
shared across agents
One store, many writers. CORAL gives four concurrent agents a common attempts / notes / skills filesystem.

Rejected edits are their own question: SkillHone keeps a decision history of what it declined; DGM leaves no trace of a broken child.

D5 Search How are candidates produced, and which are kept?

Topology — how candidates are produced

none
No candidate set at all. Ouroboros runs evolution tasks in sequence.
greedy
One candidate, take it or leave it. Living-Harness commits once per episode.
archive
Any past survivor can be the next parent. DGM samples from the whole tree.
population archive
Parallel branches that can be merged. DarwinX recombines lineages.
lineage tree
Structured descent with bandit selection. Mendel GM uses clade-level Thompson sampling.
Pareto frontier
Keep what is best on some axis. Meta-Harness maintains a score–cost frontier.
agent-directed
No fixed topology; the optimizer decides. OEO chooses when to branch, roll back, or stop.

Gate — which candidates are admitted

functionality
Does it still run? DGM admits any child that compiles and can still edit code, improvement or not.
strict improvement
Validation must not drop. HCL rejects anything that regresses.
preserve-and-extend
Gain something, break nothing. DarwinX requires positive gain with bounded regression.
peer review
Another agent decides. SkillHone issues accept, reject, or request-changes.
optimizer-chosen
No external gate. OEO commits and picks its own final checkpoint.

D6 Recursion Is the editor itself in the edit set?

no
The optimizer is fixed; only its target moves. Meta-Harness freezes its outer loop by design.
partial
The agent rewrites its own editing code, but the machinery choosing what to try stays fixed. DGM.
yes
The procedure that performs modifications is itself modifiable. Hyperagents.

DGM — Darwin Gödel Machine arXiv 2505.22954

D1 Object
harness code, whole-repo agentic edits — its own Python repository: tools, prompts, control flow. One feature per child.
D2 Editor
agent with tools — the agent rewrites its own repo. Diagnosis comes from a separate frozen model (o1), not the editing agent. Bandwidth not reported.
D3 Evidence
verifier or tests, external — one run's logs, the GitHub issue, the predicted patch, and the benchmark's private test patch, read by the diagnosis model.
D4 Memory
raw archive — a tree of every functioning ancestor's code. Rejected edits discarded: broken children leave no trace.
D5 Search
archive topology — any functioning ancestor can be sampled as parent, ∝ sigmoid(score) × 1/(1 + children). Gate: functionality — the child compiles and can still edit code. No score requirement.
D6 Recursion
partial — the agent edits the code that does the editing, but parent selection and the diagnosis model stay frozen.

Mendel GM arXiv 2608.07645

D1 Object
harness code, free-form self-rewrite — agent source plus scaffolding, treated as a genotype. No code splicing between lineages.
D2 Editor
agent with tools — the target agent edits its own code. Evidence budget: two (trajectory, outcome) records per edit; a retained clonal operator uses one, at λ = 0.10.
D3 Evidence
paired comparison, external — two runs differing in exactly one respect: same agent on two tasks, or two lineages on one task. Binary verifier outcomes.
D4 Memory
raw archive — a tree storing code and every recorded phenotype, plus a global failure pool the released configuration neutralises at βfail = 1.0. Rejected-edit memory not reported.
D5 Search
lineage tree — clade-level Thompson sampling with a widening rule Nα ≥ |V|. Gate: validation pass — admits any child that validates.
D6 Recursion
partial — the agent rewrites itself; the search machinery is untouched.

Hyperagents arXiv 2603.19461

D1 Object
harness code, whole-repo — the task agent, its tools and memory, and the meta agent's own modification procedure.
D2 Editor
agent with tools — the system's own meta agent, using bash and file editing. Bandwidth: about 33M self-modification tokens per 100-iteration run.
D3 Evidence
scalar score, external — archive scores and prior per-domain evaluation results.
D4 Memory
raw archive of hyperagents. Agents introduced their own persistent memory and a PerformanceTracker during runs. Rejected-edit memory not reported.
D5 Search
archive topology — parent sampling ∝ sigmoid(score − top-3 mean) × novelty. Gate: functionality — admits if it compiles.
D6 Recursion
yes — the meta-level modification procedure is itself an edit target. Parent selection remains frozen.

Ouroboros arXiv 2608.08311

D1 Object
harness code, whole-repo commits — its own repository: tools, prompts, context assembly, review logic, core code.
D2 Editor
agent with tools — the agent itself plus scout and acting subagents in worktrees; the parent is the sole committer. Bandwidth not reported.
D3 Evidence
LLM judge, self-reviewed — a blocking diff-review panel, deterministic preflight, and fingerprint freshness, plus observed bugs.
D4 Memory
compiled artifacts — durable error classes, a review-evidence ledger, Git history, 227 MB of memory artifacts. Rejected-edit memory not reported.
D5 Search
none — sequential agent-directed evolution tasks, no candidate set. Gate: peer review (a blocking quorum) together with functionality; no score-based acceptance.
D6 Recursion
yes — including the review logic that gates its own edits. Excludes an unmodifiable launcher and supervisor.

Meta-Harness arXiv 2603.28052

D1 Object
harness code — the harness as a single-file executable Python program. The proposer chooses a local edit or a full rewrite.
D2 Editor
agent with tools — a coding agent running grep and cat over the filesystem. Bandwidth: about 10 MTok per iteration, median 82 files, against 0.002–0.026 MTok reported for prior text optimizers.
D3 Evidence
execution traces, external — search-set scores plus the raw traces of every prior candidate, searchable rather than summarised.
D4 Memory
raw archive on the filesystem: code, scores, and traces per candidate. Regressions retained and reasoned over; smoke-test failures not logged.
D5 Search
Pareto frontier, agent-directed — no parent selection or mutation operators. Gate: interface smoke test; the proposer never sees test-set results.
D6 Recursion
no — the outer loop is deliberately frozen.

DarwinX arXiv 2608.07545

D1 Object
harness code plus skill file — a skill layer (prompts, memory) and a code layer (tools, control flow). Additive single edits.
D2 Editor
agent with tools — an LLM proposer plus a reasoning verifier agent. Bandwidth not reported.
D3 Evidence
verifier, three routed signals — failure diagnosis, teacher demonstrations, and self-contrast, scored by the benchmark's own verifier at avg@k without gold labels.
D4 Memory
raw archive that never deletes, plus shared cross-generation memory of themes that worked or regressed. Rejected edits retained as stepping stones.
D5 Search

D6 Recursion
no — selection machinery is fixed.

RHI — Recursive Harness Self-Improvement arXiv 2607.15524

D1 Object
prompt-level spec — the text describing the agent loop: roles, contracts, hops. Free-form rewrite of the whole loop.
D2 Editor
single model call — one LLM call that sees the preference history only, never the evaluation prompt. Bandwidth not reported.
D3 Evidence
LLM judge, self-generated — pairwise preference against the immediately previous revision.
D4 Memory
linear history — the preference record over a single lineage. Rejected-edit memory not reported.
D5 Search
greedy single-lineage hill-climb. Gate: none — every revision is kept; the loop stops when the improvement rate falls below ε.
D6 Recursion
no, despite the name. By the update rule H(i+1) = L(H(i), D(i)) the optimizer is a fixed external model: the recursion runs over revision history, not over the editor.

Living-Harness arXiv 2607.26598

D1 Object
memory and context — episodic-memory entries and a state graph. Bounded, schema-constrained JSON commits; no code is touched.
D2 Editor
reflective call under a fixed procedure — an extract-then-commit pipeline running under a frozen, hand-written Evolution-SOP. Sees the full trajectory plus evaluator signals.
D3 Evidence
verifier, external — evaluator signals and trajectories, scored before the update is applied.
D4 Memory
compiled artifacts — memory entries plus state-graph repair edges, portable across model backbones. Rejected candidates discarded.
D5 Search
greedy per-episode commit, no population. Gate: five checks — schema, scope, evidence, constraint, merge. No rollback.
D6 Recursion
no — the Evolution-SOP is frozen and hand-written.

OEO — Open-Ended Optimization arXiv 2608.09629

D1 Object
skill file — a text artifact; Revise commits a new version. The harness itself is frozen.
D2 Editor
agent with tools — emits Inspect / RunTarget / Revise / Select / Stop. Bandwidth: a median 34.3% of the reference target-interaction token budget.
D3 Evidence
execution traces plus scalar score, external — optimizer-chosen inspection of data and results, plus RunTarget rollouts scored outside the loop. The sealed split is untouchable.
D4 Memory
linear history plus a checkpoint list, with rollback via Select. Rejected-edit memory not reported.
D5 Search
agent-directed, no prescribed topology. Gate: optimizer-chosen — no external gate; it commits and self-selects the final checkpoint.
D6 Recursion
no — the improvement process is composed online but is not itself an edit target.

Harness-R1 arXiv 2608.02276

D1 Object
harness code as an executable runtime overlay at four lifecycle hooks. Bounded, validated patch; the target agent itself is frozen.
D2 Editor
trained editor — a 9B engineer model trained with GRPO to emit patches, one generation per patch. It reads a compacted failure packet, not raw traces.
D3 Evidence
scalar score, external — the realized success delta from rerunning the frozen target on the same task batch.
D4 Memory
none — no patch memory persists across batches; only the engineer's weights carry forward. Invalid patches are not stored.
D5 Search
no topology — GRPO samples K = 8 candidate patches per step. Gate: validity — invalid patches score zero.
D6 Recursion
no — the engineer is a separate model from the frozen target it patches.
