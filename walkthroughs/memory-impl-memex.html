Memex: keep a short index, reopen the evidence

2 min · 1 worked example · 2026-09-21

All methods

The idea: remove bulky evidence from the active conversation, keep it under a stable address, and leave a short reminder of where it is.

Our invented agent is debugging a cache collision. A long test log is filling its context.

1. The agent decides it can put the log aside

The prompt includes context-usage information. The agent chooses to compress now; the threshold is not itself a mandatory summarization command.

It still needs to remember that the test failed and where to recover the evidence.

2. The agent submits a compression call

The call contains two things:

  • A short summary: “Two-tenant test failed. Evidence is under failure_1.”
  • A block to store under failure_1, either authored text or an anchored span selected from the existing log.

The short summary is an index, not the full evidence.

3. The program stores the block

For an anchored block, ordinary code locates the supplied start, middle, and end anchors and extracts the span.

The external store now maps failure_1 to the retained test evidence.

4. The program replaces active history

The next model input keeps the fixed instructions, task, and short summary. The bulky intervening history is gone from that input.

The external block survives this replacement.

5. The agent later needs the exact failure

It sees the summary's pointer and calls ReadExperience for failure_1.

The program returns that one block as a tool observation. The relevant detail is back in the active context.

6. The agent continues the investigation

It uses the recovered evidence, edits the key, and runs a new test against the changed code.

It did not have to keep the original log visible during every intervening call.

What persists: the task's external blocks and current short context. This is not automatically a bank shared by unrelated tasks.

What MemexRL adds: training rewards successful task completion and penalizes inefficient or malformed behavior, teaching the model when and how to use these tools. The outcome trains earlier choices; it is not supplied in advance to the writer.

The defining operation is: save evidence → leave an address → shorten context → read that address when needed. Exact schemas, validation, and training are below.

What you are building

Implement two memory tools inside the ordinary agent loop. CompressExperience writes selected blocks to an external store and replaces active history with a short index-bearing summary. ReadExperience brings a chosen block back into active history.

The agent chooses when to invoke them. Memex is the interface and loop; MemexRL additionally trains the policy operating that interface.

This chapter follows the pinned memory mixin, with the indexed-store mode separated from the release's summary-only and RAG variants.

Step 1 — Define active and external state

messages = [
    {"role": "system", "content": "Agent instructions"},
    {"role": "user", "content": "Investigate the cache collision"},
]
archive = {}       # db_index -> stored block
segments = []      # training/diagnostic records, not solver-visible memory

The first two messages have a special role in the inspected implementation: compression literally keeps them and replaces the rest. If your harness has additional fixed messages or later user requirements, map them deliberately; do not reuse that positional assumption blindly.

The external archive survives compression within this task. The procedure starts each task with a fresh store.

Step 2 — Expose status and let the policy choose

After tool observations, report context usage. The paper's status distinguishes working size, total size, and a threshold. It is a soft signal: the model may compress now, retrieve, perform another task action, or finish.

A threshold does not itself specify which details to preserve. The model must author both a useful summary and recoverable block addresses. The tool prompts are part of that policy interface.

Step 3 — Implement both block-writing paths

The literal code argument names are summary and db_blocks. An authored block looks like:

{
  "summary": "The two-tenant test failed. Investigate make_key. Raw failure: failure_1.",
  "db_blocks": [
    {
      "db_index": "failure_1",
      "db_content": "The test returned equal keys for distinct tenants."
    }
  ]
}

An authored block is already a summary. For evidence that must be recovered more exactly, select an existing span using three ordered anchors:

BEGIN cache test
test_two_tenants FAILED: identical keys
END cache test

{
  "db_index": "failure_1",
  "start_anchor": "BEGIN cache test",
  "mid_anchor": "test_two_tenants FAILED",
  "end_anchor": "END cache test"
}

The runtime—not the model—extracts the span. An exact-path teaching implementation is:

def anchored_span(source, start, mid, end):
    p = source.find(start)
    while p >= 0:
        m = source.find(mid, p + len(start))
        while m >= 0:
            e = source.find(end, m + len(mid))
            if e >= 0:
                return source[p:e + len(end)]
            m = source.find(mid, m + 1)
        p = source.find(start, p + 1)
    raise ValueError("anchors not found in order")

The release additionally tries whitespace-normalized matching. That fallback returns whitespace-collapsed text, not identical original bytes. It can also combine authored content with extraction, including an extraction placeholder. Keep that distinction if exact evidence matters.

Step 4 — Validate before committing the replacement

Check the summary is nonempty; the block list exists in indexed mode; each ID is valid; IDs do not repeat inside the request; and each block has authored content or a complete valid anchor set.

The release permits updating an already stored ID but rejects duplicate IDs within one compression request. Its ID syntax permits letters, numbers, underscores, and dashes, with a maximum length of 64.

Resolve every block before mutating state. This simplified authored-block path illustrates the commit:

import re

def compress_authored(messages, archive, summary, blocks):
    if len(messages) <= 2 or not isinstance(summary, str) or not summary.strip():
        raise ValueError("invalid compression")
    if not blocks:
        raise ValueError("blocks required")
    resolved = {}
    for b in blocks:
        key, content = b["db_index"], b["db_content"]
        if not re.fullmatch(r"[A-Za-z0-9_-]{1,64}", key):
            raise ValueError("invalid block ID")
        if key in resolved or not isinstance(content, str) or not content.strip():
            raise ValueError("duplicate ID or empty content")
        resolved[key] = content
    next_archive = dict(archive)
    next_archive.update(resolved)
    next_messages = messages[:2] + [{"role": "user", "content": summary}]
    return next_messages, next_archive

This reconstruction omits the release's metadata, compression header, optional summary cap, and training-segment capture. It makes the central state mutation explicit; it is not a drop-in class replacement.

Step 5 — Make retrieval change the next prompt

When the model calls ReadExperience(db_index="failure_1"), look up that exact ID and return its content through the tool channel. Append the resulting observation to the active messages.

Do not return all archived blocks. Do not re-run the original test merely to reconstruct information that was stored. The model decides which ID to dereference using the indexed summary.

A failed lookup returns an error; it should not invent an empty success. If the summary forgot which IDs exist, the archive can contain useful evidence that the agent never asks for. Index quality is therefore part of writing quality.

Follow the whole trace

1. Read implementation; run test; receive the failure log.
2. CompressExperience:
     active := system + task + "failure_1 holds the regression evidence"
     archive["failure_1"] := selected evidence
3. Continue investigating using the shorter active prompt.
4. Need exact failure detail:
     ReadExperience("failure_1")
5. Tool observation reintroduces "identical keys" into active context.
6. Edit the key and run a new test against the changed state.

A new test after a code change is not redundant just because a similar test command was run earlier.

“Lossless” is a release mode name. Selected authored blocks can be lossy, unselected history is absent, and the index can be inadequate. The mechanism offers dereferencing of retained evidence, not an unconditional full-history guarantee.

Step 6 — Implement MemexRL's training records and objective

Preserve each pre-compression segment and each subsequent segment's actual inherited summary. All segments from a rollout share its terminal return. Do not reconstruct later training prefixes from the complete raw transcript.

The paper's return is:

\[ R=R_{\mathrm{task}}-P_{\mathrm{context}}-P_{\mathrm{redundancy}}-P_{\mathrm{format}}. \]

The normalized penalty definitions are:

\[ P_{\mathrm{context}}=\min\left(1,\frac{\sum_{t\in\mathcal I}\max(0,C_t-\tau)}{\tau\,T}\right),\quad P_{\mathrm{redundancy}}=\frac{N_{\mathrm{redundant}}}{N_{\mathrm{nonmemory\ calls}}},\quad P_{\mathrm{format}}=\frac{N_{\mathrm{malformed}}}{N_{\mathrm{attempted\ tool\ steps}}}. \]

Here \(\mathcal I\) indexes non-compression steps, \(T\) is the total trajectory step count, \(C_t\) is context size, and \(\tau\) is the soft threshold. Compression steps are omitted from the overflow numerator, not from the total-step denominator. Redundancy means repeating an identical non-memory tool signature without an intervening state change. Declare a zero-denominator convention for runs with no relevant calls; do not let a NaN become a measured score. The equation uses reconstructed notation for the paper's penalty components.

Released shaper details: the reward code applies configurable weights to these components; its class defaults are 0.5, 0.3, and 0.2. Its format ratio counts steps with format errors, not every individual parse error. Empty relevant counts produce zero component penalty. Those choices must be recorded when matching a run.

This normalized teaching helper reproduces its overflow calculation:

def context_penalty(steps, threshold, weight=0.5):
    if threshold <= 0:
        raise ValueError("positive threshold required")
    overflow = sum(max(0, step["context_length"] - threshold)
                   for step in steps if not step["compressed"])
    ratio = min(1.0, overflow / (threshold * len(steps))) if steps else 0.0
    return -weight * ratio

For context lengths [150, 1000, 100], threshold 100, and compression only in the middle step, the ratio is 50/300, not 50/200. The compression removes that step's overflow contribution but does not remove the step from the denominator.

Sample a group of rollouts for one task, compute \((R-\mathrm{mean})/(\mathrm{std}+\epsilon)\), and apply a clipped policy-ratio objective to generated tokens under each segment's real prefix, with optional reference-policy KL. The policy is warm-started with well-formed memory demonstrations. Training procedure and equations

Concretely, calculate each generated token's likelihood ratio \(\rho=\exp(\log\pi_\theta-\log\pi_{\mathrm{old}})\) under its saved prefix. Maximize the clipped term:

\[ \min(\rho A,\operatorname{clip}(\rho,1-\epsilon_c,1+\epsilon_c)A). \]

Apply the selected token/segment reduction and reference-KL configuration from the training recipe. Tool observations and inherited summaries are input, not newly sampled policy tokens in the receiving segment.

For an invented two-rollout example, one return is 1 and another 0: normalized advantages are approximately +1 and -1. Every segment in the successful rollout receives its positive advantage, including an early compression that only paid off much later. The verifier's answer/outcome is supervision; it was not inserted into the original memory tool arguments.

Tests and reproduction boundary

Test invalid anchors, duplicate IDs, existing-ID updates, missing retrieval, two consecutive compressions, and exact post-compression message contents. For RL, verify a sampled token's training prefix equals the prefix seen during rollout.

Giving these tools to a frozen model implements a Memex-style runtime. It does not reproduce MemexRL's learned behavior without its training procedure and checkpoint.
