Agent Memory: Notes, Search, and Compression

26 min · 31 papers · 2026-09-15

Research cut: 15 September 2026. A decision guide, not a leaderboard. Frozen APIs, trainable policies, and learned representations are all in scope. Recommendations and proposed experiments are my synthesis; numerical results are the papers’ reports, not reproductions.

Start here: a broad map, not a single recipe

The goal is to understand what each family of work makes possible, where its evidence stops, and which ideas can be recombined. A useful memory system must decide what to preserve, how to represent it, how to find it, when to use it, and how to revise it. Different papers improve different parts of that cycle.

Three questions organize the literature:

  1. What should survive? Exact evidence, factual notes, reusable lessons, executable skills, or a learned representation? These preserve different kinds of information.
  2. What should enter the next context? Retrieved passages, a running summary, recoverable source pointers, or compressed latent states? Keeping the source does not require displaying it all.
  3. What should learn from experience? The memory contents, retrieval scores, writing/search policy, compressor, task model, or outer optimizer? “Continuous learning” can refer to any of these.

Your first experiment remains inner-agent notes + grep after restart. That sets implementation order, not reading scope. Compression, consolidation, trained memory, and outer-loop learning remain substantial parts of this review. The experiment companion is optional until you are ready to implement.

Reading routes: notes and restart · compression · outer-loop learning · ideas to borrow · newest work and cautions.

What should we evaluate on? The benchmark review separates searchable experience, held-out action, online learning, reset/resume, and compression, with a broad non-coding reference shelf.

For the first experiment, read ShadowFrog → PRO-LONG → ReasoningBank, then AutoMem to understand how the writer/searcher could eventually be trained. For compression, read Memex → MemAgent → Cartridges, then Still/ContextPilot. For later outer-loop learning, read Meta-Harness → HCL. These routes are prioritized subsets; the rest is a reference shelf, not a prerequisite reading list.

Do not collapse four different budgets into “memory.” Disk bytes, prompt tokens, GPU KV bytes, and training FLOPs are different resources. Keeping everything on disk can coexist with aggressive prompt compression. Keeping a fixed compression ratio does not imply a fixed absolute memory size.

Track A — taking notes, restarting, and grepping later

1. ShadowFrog — make the location predictable

Report · Code · June 2026 engineering report/release.

Mechanism. Knowledge about src/auth.py goes in .shadow/src/auth.py.md, with symbol-level sections and cross-file links. The source path becomes an address for its corresponding notes. These are curated discoveries, not a complete transcript archive. The larger system also explores through experiments and consolidates notes.

The 97.6% versus 36.2% result. The authors plant facts, then ask the agent to retrieve relevant prior knowledge. In the highlighted Django setting there are roughly 2,500 planted facts, the file path is supplied, and the agent gets eight tool calls. Mirrored files achieve 97.6% recall; one large notes file achieves 36.2%. With much more search budget, the flat layout catches up. This is a retrieval-under-budget experiment, not a 61.4-point coding improvement.

Sharp takeaway. Organization can substitute for search intelligence when the task supplies a good address. A research question often does not supply a file path: test topic/source/entity indices as well as literal mirroring.

Try: identical note content in a monolith, flat files, and a hierarchical index. Keep the model and read budget fixed. Disable autonomous “dream” exploration in this comparison: extra experience is a different intervention.

2. PRO-LONG — archive the evidence, compute over it

Paper, §2.2 and §3.2 · Code · July 2026 preprint · existing deeper tutorial.

Mechanism. Append structured actions, outcomes, board states, and summarized plans to a log. The agent reads selectively using grep/regex and Python. The archive is not pasted wholesale into the prompt.

Evidence to focus on: the tool ladder scores 23.1 with read-only access, 27.2 after adding grep/regex, 38.3 after adding Python, and 41.2 with the full tools. These are the paper’s ARC-AGI-3 scores, not binary percentages of all games solved. The largest increment is programmatic analysis, not grep alone. Each game/run starts fresh; the experiment does not transfer memories between games.

Sharp takeaway. “Keep everything and search” includes computation: find a score change, compare states, reconstruct an event sequence. Grep is a candidate generator, not the whole reader.

Try: raw archive + grep versus raw archive + grep/Python, then add notes on top. This tests whether notes contribute abstraction beyond what a competent archive reader can reconstruct. Treat cross-task reuse as your extension, not a published PRO-LONG result.

Companion: Recursive Language Models — make the source a programmable object

Paper, v3 §2 and §5 · Code · December 2025; revised May 2026.

Mechanism. Put the long input in an external REPL variable. The model writes programs to inspect, partition, and invoke sub-models on selected pieces; intermediate results also live outside the main prompt. This extends selective access into semantic computation over many pieces, not just finding one passage.

Why read it. Its evaluations distinguish sparse retrieval from information-dense aggregation. A task depending on nearly every record cannot be solved by finding one excellent snippet. The revised paper also trains smaller models to use this interface.

Sharp takeaway. “External memory” can be an execution substrate, not merely a database. The new bottleneck is choosing a sound decomposition and controlling sub-call cost. The paper reports wide cost/runtime variation and warns about exploding sub-calls. Its persistent REPL within an invocation does not, by itself, establish cross-task memory.

Idea to borrow: let a reader compute over accumulated notes/evidence and use bounded semantic sub-calls where lexical search cannot answer the question. Keep grep-only access as the simpler comparison.

3. ReasoningBank — save the lesson, not just the episode

Paper, §3.2; Table 2; Appendix A.2 · Code · September 2025; revised March 2026; ICLR 2026 acceptance stated on arXiv.

Mechanism. After a task, judge success/failure and extract up to three items with title, description, and reusable reasoning content. Retrieve items from similar previous experiences before solving the next task. The default retrieves one experience’s items. “Consolidation” in the core implementation is simply appending—not sophisticated merging or forgetting.

Evidence. With Gemini-2.5-Pro, SWE-bench Verified resolve rate is 54.0 without memory and 57.4 with ReasoningBank; average interaction steps fall from 21.1 to 19.8. The paper also evaluates web tasks. Its MaTTS extension adds extra trajectories and should be evaluated separately from the memory-only method.

Sharp takeaway. The key experimental variable is what gets written: a transferable strategy versus a raw trace or successful routine. This is a particularly clean baseline because the surrounding retrieval pipeline is deliberately simple.

Try: the same reader over raw episodes, success-only lessons, and success-plus-failure lessons. Audit failure explanations against available evidence: an agent can confidently teach itself the wrong diagnosis.

4. ACE — edit individual notes instead of rewriting your memory

Paper, §3 and §4.2 · Code · October 2025; arXiv lists ICLR 2026.

Mechanism. A generator acts, a reflector identifies lessons, and a curator proposes small playbook changes. Identified bullets carry helpful/harmful counters. Deterministic merge logic applies deltas; refinement controls duplicates. Online evaluation predicts before updating from the current example.

Why it belongs here. A running summary repeatedly exposes old knowledge to rewriting. ACE instead makes preservation the default and local change explicit. Its context-collapse case study includes an 18,282-token playbook rewritten into 122 tokens; this is a motivating example, not a universal probability of summary failure.

Sharp takeaway. The benefit is not “longer prompts are always better.” It is update locality: adding one new lesson should not require regenerating every old lesson. A long playbook still needs scoped retrieval when it no longer fits.

Try: whole-summary rewrite versus append-only versus ID-addressed deltas, with the same writer and prompt budget. An “ACE writer + grep reader” is a useful adaptation, but label it as such; it is not automatically the original paper configuration.

5. MemRL — learn usefulness without updating the LLM

Paper, §4; Table 2 · Code · January 2026 preprint.

Mechanism. Store intent, experience, and a utility value. First retrieve semantically compatible candidates; then rank using normalized similarity and utility. After observing reward, update the utilities of memories actually injected. The LLM stays frozen.

The implemented Monte Carlo-style update is Eq. 4:

\[ Q_{\mathrm{new}}\leftarrow Q_{\mathrm{old}}+\alpha(r-Q_{\mathrm{old}}). \]

Here \(Q\) is a memory’s estimated utility, \(r\) the observed reward, and \(\alpha\) the learning rate. Intuitively: nudge the note’s score toward how the task turned out.

Evidence. Held-out BigCodeBench success is 50.8% versus 48.5% without memory; ALFWorld is 97.9% versus 83.6%. These transfer results are more relevant than its cumulative “solved at least once” score over ten training epochs.

Sharp takeaway. A high-Q note may merely be used on easier tasks. When several notes are injected together, all receive ambiguous credit. The stationarity assumptions in the analysis do not guarantee safety after a repository, task distribution, or model changes.

Try: freeze the note content and compare similarity-only retrieval against utility ranking. Then test on new tasks with utilities frozen; separately evaluate online updating under drift.

6. AutoMem — train the note-taker/searcher as a specialist

Paper, §2; Table 1 · Code · July 2026 preprint.

Mechanism. LOG writes memory files; PLAN reads/searches them before acting. Loop 1 optimizes prompts, schemas, and tools by reviewing full trajectories. Loop 2 selects good memory-operation turns from the agent’s own traces and trains a LoRA memory specialist. The task-action model remains unchanged. For the first notes + grep baseline, borrow the LOG/PLAN separation without running either optimization loop.

Actual AutoMem framework figure. Read the split at the bottom: the trained component manages memory; a separate frozen model commits world actions. Source: authors’ repository, commit 1987b8f.

Evidence. Crafter progression goes 25.00 → 47.27 after scaffold optimization → 51.36 after memory training. Thus the headline roughly 2–4× gains are not the incremental benefit of fine-tuning. The evaluations are games, with limited seed counts and repeated evaluation used for scaffold selection.

Sharp takeaway. This is a strong fit for training “write, search, read, update” independently. But freezing task-model weights does not freeze task behavior: the revised scaffold and supplied memory still change its decisions.

Try: fixed scaffold → optimized scaffold → optimized scaffold plus specialist, on held-out task seeds/families. For your setting, add a cold-start reader test and quantify whether the specialist writes notes that a different model can understand.

7. PlugMem — a richer second-wave comparator

Paper, §3; Appendix F · Code · March 2026 preprint.

Mechanism. Separate source episodes, factual propositions, and procedural prescriptions. Concepts/intents route retrieval to complete knowledge blocks; a reasoning stage condenses retrieved material for the current task. Source traces remain available for verification.

Why second wave? It tests whether structured facts plus skills beat simpler notes. The package changes writing, indexing, retrieval, and read-time condensation together, making attribution harder. Its WebArena transfer protocol also adds human demonstrations between online accumulation and offline evaluation.

Sharp takeaway. Fewer tokens injected into the task agent do not mean fewer total tokens. The appendix reports additional construction and abstraction costs. Account for those before claiming cheaper memory.

Try: add structure only after the simple note baseline is competitive; ablate graph routing and read-time condensation independently.

Track B — compression is a first-class objective

Two older conceptual anchors

  • MemGPT, 2023/2024: separates a small active context from larger external memory and lets the model manage movement between them. Read it for the virtual-memory analogy and control flow—not for a claim of literally unlimited usable knowledge. It connects multi-session memory and document analysis under one interface.
  • ICAE, ICLR 2024 · code: trains an encoder to turn context into compact continuous memory slots that a frozen decoder can use. Reconstruction/language-model pretraining precedes instruction tuning. It is a useful ancestor for understanding the representation question: preserving text exactly and preserving the ability to answer downstream questions are different objectives. These anchors are conceptual summaries, not full reviews here.

8. LLMLingua-2 — the inexpensive discrete-text control

Paper · Code and model links · Findings of ACL 2024.

Although older, this is a useful practical anchor: a small bidirectional encoder classifies which tokens to keep, producing ordinary compressed text that a frozen API model can consume. No custom KV interface is needed.

Sharp takeaway. Extractive does not mean semantically lossless. Dropping “not,” a unit, a condition, or a source attribution can change a claim without introducing any new token. Compare it with simple truncation and an abstractive summary at the same final input budget, including compressor latency.

This is prompt compression, not cross-task learning. That is a scope label, not a reason to exclude it.

9. Memex / MemexRL — compress the working view, retain source blocks

Paper, §3 and §5.1 · Code · March 2026 preprint.

Mechanism. Replace a long working context with a compact summary containing stable indices. Archive underlying blocks separately; ReadExperience(index) restores details. MemexRL trains the writing and reading decisions, including penalties for context overflow, redundant tool calls, and malformed calls.

Evidence and caveat. Reported success rises from 24.2% to 85.6%, with peak working context falling from 16,934 to 9,634 tokens. But this is a modified ALFWorld setup: look is allowed once and summaries are truncated to 300 tokens, explicitly creating a need for archived IDs. Do not treat that gain as a general research-agent effect size.

Sharp takeaway. The design is more transferable than the headline number. “The archive contains it” is weaker than “the reader can find it.” A summary that deletes the only useful pointer has effectively lost the information under a finite search budget.

Try: keep summary text identical and toggle dereferencing. First test a prompted implementation; add RL only after the archive/index mechanics work. Persisting the store across tasks is an additional experiment, not established by this within-episode evaluation.

10. MemAgent — a learned, bounded textual memory

Paper, §2.1; Tables 1 and 3 · Code · 14B checkpoint · July 2025; revised July 2026; ICLR 2026 Oral stated on arXiv.

Mechanism. Read a document chunk, overwrite a bounded ordinary-text memory, repeat, then answer. RL uses final-answer reward to train memory-writing turns across their distinct contexts. The question is available during reading.

Actual MemAgent method figure. The memory is text, not an embedding or KV cache. Each overwrite is an information bottleneck. Source: arXiv v2.

Evidence. The v2 table gives 14B accuracy of 80.47 at 7K and 71.09 at 3.5M tokens on RULER-HQA. That is a 9.38-percentage-point drop; do not repeat “lossless” or the abstract’s under-5% wording without checking the version and comparison. LongBench-QA offers a more varied complement to needle retrieval.

Sharp takeaway. Knowing the question while compressing is a major advantage. A note-taker preserving information for unknown future tasks faces a harder problem. Test both query-aware and query-blind compression; do not attribute their difference solely to compressor quality.

Try: prompted overwrite and trained overwrite at identical chunk/memory sizes. Add unseen query types, growing evidence density, and repeated re-use of the same compressed document.

11. AgentFold and ContextPilot — learned context editing

AgentFold paper · ICLR 2026 version · inference code.

AgentFold: keep the latest interaction intact, summarize individual older steps, and merge a completed multi-step investigation into a coarser block. Train these folding decisions with SFT. Its reported BrowseComp score is 36.2% for the 30B-A3B agent. The baseline lesson is that a finished subproblem is a natural compression boundary; a still-uncertain lead often is not. Lossy folding can nevertheless erase evidence needed later. The public directory inspected contains inference/serving code; I did not verify a complete matching training-data release.

ContextPilot paper · code · August 2026; accepted EMNLP 2026 Main per arXiv · existing tutorial.

ContextPilot: combine notes, structured memory, search, planning, and recoverable context offloading. RL branches at sensitive context decisions and estimates snapshot value from descendant outcomes. On its four long-context QA benchmarks, the 8B SFT average is 65.78; RL reaches 69.40. The trained system uses a 32K window. Giving the untrained 8B model the tools alone scores only 27.61.

Sharp takeaway. A tool interface is a skill requirement, not free capability. The strongest training comparison is SFT versus RL within the same interface, then uniform versus targeted branching at matched rollout cost. Do not compare AgentFold’s headline directly with ContextPilot’s deep-search table: the latter mixes pass@3 and pass@1 metrics across benchmarks.

12. Cartridges — fit a reusable latent representation of a corpus

Paper, §4 · Code · June 2025.

Mechanism. For a particular corpus, generate varied synthetic conversations and optimize a small KV prefix so the frozen model behaves like a teacher with the corpus in context. At serving time, load the cartridge and answer many different queries.

Evidence. The paper reports matching ICL quality with up to 38.6× less KV memory and 26.4× higher throughput. Those are KV/serving results—not 38.6× less total GPU memory or 26.4× lower request latency.

Sharp takeaway. This is closer to compiling a corpus than taking a running note. The key variable is reuse: a frequently queried stable paper collection may justify fitting; a rapidly changing stream may not. Also test which kinds of questions the synthetic self-study failed to cover.

Try: a fixed corpus with many held-out queries; sweep cartridge size and queries per corpus. Compare total preparation plus serving cost with cached full-context and retrieval baselines. Measure rebuild cost after source changes.

13. Still — learn the compactor once, apply it to new caches

Paper, §2.3–2.4 · June 2026 preprint. No official implementation/checkpoint was located in this review; treat it as a research/reimplementation candidate, not a verified drop-in baseline.

Mechanism. Small per-layer Perceivers transform full KV states into synthesized compact KV states. Train the compactor against a frozen full-context teacher; perform one compactor forward pass per new context. Unlike Cartridges, the optimization is amortized across contexts rather than performed separately for each corpus.

Evidence. The matched-training RULER comparison reports 8–22-point gains over KV-Distill in 16 of 18 cells. The paper also evaluates summarization and iterative ingestion; the latter experiments are single-seed, explicitly labeled.

Sharp takeaway. Its iterative cache grows as \(T/c+ct\), where \(T\) is ingested length, \(c\) the local compression ratio, and \(t\) the compact block length. This is linear growth at a reduced rate, not constant-sized infinite memory. Full KV construction is also required before compaction.

Try: static and repeated compaction separately. Compare with token selection at matched retained KV bytes and include prefill/compaction time and temporary peak memory.

Later: memory for the optimizer, not only the task solver

An inner agent remembers how to solve a task. An outer agent remembers which interventions improved a solver, which failed, and under what evaluation conditions. Their memory tools can be identical; the evidence they should store is not. Treat this as a later experiment after inner-agent notes + grep is established.

14. Meta-Harness — search the history of optimization attempts

Paper, §3; Table 3 · released TerminalBench artifact · March 2026 · existing tutorial.

Mechanism. An outer coding agent navigates directories containing candidate code, scores, and full execution traces, then proposes a new harness. Grep makes a large optimization history selectively readable.

Evidence. In the classification interface ablation, median candidate accuracy is 34.6 with code/scores, 34.9 with added summaries, and 50.0 with raw-trace access. These are search-set outcomes, not held-out gains. The inspected public artifact contains the discovered TerminalBench agent, not a complete general-purpose search engine.

Sharp takeaway. Optimizer summaries can discard the very evidence needed to diagnose an unsuccessful edit. But this comparison does not prove all compression is harmful: it tests particular summaries and readers. Keeping searchable raw traces is a strong control.

Try later: optimizer with no history, score/code history, raw searchable traces, then traces plus distilled lessons. Transfer the optimizer’s memory to a new benchmark while resetting the starting inner harness. Otherwise, improved performance may only reflect transfer of the already-optimized harness. The paper’s TerminalBench search/final evaluation uses the same 89 tasks, so it does not supply this held-out transfer test.

15. Harness Continual Learning — successful updates can still cause forgetting

Paper, §3.3; Table 2 · August 2026 preprint · existing tutorial. No official implementation was verified in this review.

Mechanism. Propose a new harness state, then gate commitment on current improvement, historical retention, and validity. The state includes interface, memory, capabilities, and routing. Prior cases used for the retention gate are separate from final test cases.

Evidence. On ALFWorld, the stability-oriented variant has final average 61.74 and forgetting 2.64; the permissive variant has 62.98 and 10.94. These are averages across task categories, with memory baselines reimplemented inside the authors’ framework.

Sharp takeaway. Even zero allowed loss on retained anchors does not imply zero loss on held-out old tasks. A gate is a finite regression test, not a proof against forgetting. Repeated selection also makes its evaluation budget part of the method.

Try later: the same note/update proposer with and without retention checks. Preserve an untouched final test set and charge for every candidate evaluation. This is a gate ablation, not yet evidence that the outer optimizer’s own policy has learned.

A shared example: what should survive?

This is an invented example for reasoning about the designs, not a paper result.

A research agent spends 40 tool calls investigating a result. It learns that a reported “20% improvement” is relative, applies only to a particular subgroup, and uses a changed evaluation script. Tomorrow it must explain another result from the same project. During a later update, that script changes again.

Durable evidence: source versions, passages, scripts, observed outputs
       │
       ├─ searchable notes: claim, condition, caveat, exact evidence pointer
       │       └─ new task → search → verify applicability → read evidence
       │
       └─ compact working state: current goal, checked facts, open questions
               └─ restart → restore state → dereference only what is needed

The raw archive preserves the qualifier, but the reader must locate it. A useful note says when the claim holds and where it is supported, not “be careful comparing results.” A reusable lesson says “verify denominator, split, and evaluator version before comparing scores.” Those are different memory objects.

Lossy compression might retain “20% improvement” while removing the subgroup condition. Pointer-based offloading can recover the passage, but only if the pointer remains discoverable. A learned KV representation might answer the original evaluation question well yet fail an unexpected question about the script version.

When the script changes, an old successful procedure may become harmful. Preserve provenance and validity scope; do not merely increment its success count forever. The same issue appears in coding as commit/API drift, but it is equally important in research, document QA, and evolving user requirements.

What else is worth reading—and why it is not all first-batch work

  • FlexComp, September 2026: particularly relevant for adaptive compression budgets. Train one soft-token compressor with variable slot counts, then choose a budget per input. Different budgets require different encodings—not simply truncating one vector sequence. The reported 98% retention is relative to the mildest compressed setting, not full context. Work in progress; an official release was not located. Read after Cartridges/ICAE, before implementing your own budget selector.
  • PReM, July 2026: learned KV preservation and refresh during generation. Promising for adapting compression to changing evidence needs. Screened at abstract level here; implementation and full experimental controls need further checking before treating it as a reproduction target.
  • MemoryWalker, September 2026: important training-engineering warning. Eviction changes what each generated token was conditioned on; reconstructing a single final transcript can introduce conditioning mismatch or leakage. Read before training any compaction policy; not itself a note-store baseline.
  • CompactionRL, July 2026 and SWE-MeM, June 2026: task-plus-summary RL and credit assignment across compaction boundaries. Good follow-ons when training a tool-use policy. Their coding results motivate experiments, but do not establish cross-task persistence or general document compression.
  • ProactAgent, April/June 2026: pairs continuations with and without retrieval from the same interaction prefix. Useful inspiration for crediting retrieval’s incremental value, rather than rewarding every note in a successful rollout. Public implementation not verified here.
  • Proactive Memory Agent, July 2026: a separate memory agent chooses when to remind an unchanged action agent, including the option to remain silent. Relevant when the problem is using remembered constraints at the right time, not failing to store them.
  • MemHarness, July 2026: reconstruct retrieved experience for the current state rather than replaying it literally. A useful negative-transfer comparator after the basic reader works.
  • SimpleMem, January 2026 and Hindsight, December 2025 / ACL 2026 demo: useful compact/structured conversational memory controls. Include them for a conversation-history slice; their recall scores are not direct evidence of research-agent learning.
  • RSM-full, September 2026: budgeted merging and context packing. Its RealMem result does not significantly beat BM25-RAG. That is a reason to keep a strong lexical baseline, not to discard the paper. New preprint; not an established general winner.
  • Memory Decoder at Scale, July 2026: trains a separate parametric model to imitate retrieval distributions and mixes its predictions with a frozen backbone. Interesting for domain knowledge, but much heavier than a note manager or context compactor. Existing tutorial.

Ideas to borrow—not claims that the combinations already work

The following are research hypotheses suggested by reading the papers together:

  1. Use summaries as navigation, not the only surviving truth. Combine the selective access of PRO-LONG/Meta-Harness with Memex-style recovery. A note can compress where to look while the archive preserves what happened. The open question is whether a fresh reader can discover the right pointer when its future question was unknown.
  2. Let notes change abstraction level over time. Keep a concrete episode first; extract a conditional lesson after repeated support; promote a validated procedure into a skill. ReasoningBank and PlugMem motivate different stages. The risk is premature generalization: three successes under the same hidden condition do not establish a universal rule.
  3. Consolidate locally and preserve disagreement. ACE motivates ID-addressed changes; ShadowFrog motivates offline inspection and consolidation. Instead of repeatedly rewriting one master summary, preserve evidence links and superseded versions. Investigate whether consolidation reduces search cost without silently deleting exceptions.
  4. Train the reader as well as the writer. AutoMem and ContextPilot suggest that searching, query reformulation, choosing what to read, and deciding when to recover evidence are learnable skills. A bad retrieval result may reflect a poor query, not an inadequate store. Cross a fixed archive with different readers before attributing gains to memory representation.
  5. Make compression depend on uncertainty and future use. MemAgent knows the question; Cartridges amortizes across queries; FlexComp varies the retained budget. A possible hybrid spends more memory on unresolved evidence and less on verified, stable conclusions. Test unexpected future questions: confidence about today’s answer is not coverage of tomorrow’s needs.
  6. Separate remembering from intervening. MemRL, ProactAgent, and Proactive Memory Agent ask whether and when retrieved content helps. A stored note need not be injected every time it matches. A useful memory manager may improve the agent by remaining silent.
  7. Learn from unsuccessful optimization, not just successful artifacts. Meta-Harness preserves diagnostic history; HCL checks old behavior before accepting updates. An optimizer could remember “this edit failed under this evaluator and budget” without turning it into “never try this edit.” The challenge is crediting a change when several components and task conditions moved together.

One promising overall hypothesis is durable evidence + editable abstractions + a small working context, with independent learning at the read/write boundaries. But it should compete with simpler notes, pure retrieval, and lossy compression—not be assumed correct because it combines more components.

Three conclusions worth carrying into the reading group

  1. Notes and compression belong together, but at different layers. Preserve recoverable evidence; learn which small working view supports the next decision. Compare summary-only and archive-backed systems explicitly.
  2. Write policy, read policy, and representation need separate controls. ReasoningBank, MemRL, AutoMem, and Cartridges change different things. An end-to-end score alone cannot tell you which component improved.
  3. Test the boundary the system must survive. New context, new task, unknown future query, source update, and model upgrade are distinct tests. No single “long-memory” score covers them all.
