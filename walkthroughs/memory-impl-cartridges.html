Cartridges: fit a reusable numerical memory for a document

2 min · 1 worked example · 2026-09-21

All methods

The idea: train a small set of internal attention-memory tensors to stand in for a particular document or corpus. Reuse that memory for many later questions.

Our invented manual says: “Report damaged items within 7 days.”

1. Make practice questions from the manual

A model sees source material and generates requests about it. Another conversational role answers with that source available.

One practice question is: “How soon must a damaged item be reported?” The source-informed answer is “within 7 days.”

Repeat over the corpus to cover different facts and uses.

2. Save the teacher's predictions

Along with the generated answer, save the teacher's probabilities for candidate next tokens.

These are the targets that the numerical memory will learn to reproduce. No real future user's question is required yet.

3. Give the student a different source of information

The student uses the same frozen language model but receives a short, trainable key/value prefix instead of the manual.

A key/value prefix is internal attention state, not readable summary text. Initially, it may not preserve the 7-day rule.

4. Compare and adjust the prefix

Feed the practice conversation to the student. Compare its next-token predictions with the stored teacher predictions.

Backpropagation changes only the trainable prefix values, making the student's predictions closer to the teacher's. The model's ordinary weights remain fixed.

5. Repeat until the cartridge has been fitted

Train over more practice conversations and save the resulting prefix.

That saved numerical state is the cartridge for this corpus. It is not a new model that automatically compresses any document.

6. Answer a new user's question

Load the cartridge and append:

My order arrived damaged. What is the reporting deadline?

The frozen model generates an answer using the cartridge, without receiving the full manual again.

Clear this query's temporary cache before the next independent query; keep the fitted cartridge.

What persists: the corpus-specific prefix. If the manual changes, its fitted representation needs updating.

Feedback boundary: offline preparation uses source-informed teacher answers/probabilities. A future query's gold answer is not a serving input.

The defining operation is: train numerical memory for this corpus once, then reuse it across questions. This requires model-internal cache access. Tensor shapes and the exact loss are below.

Open implementation details, training, and sources

All memory methods · Short overview

A cartridge is a set of learned key/value tensors that stands in for a particular source corpus. You train those tensors offline while keeping the language model frozen. At query time, install the cartridge as the model's cached prefix and append the new question.

This requires a model implementation that exposes attention caches and permits gradients through them. A normal text-only hosted API is insufficient. This chapter follows the released cache-tuning path at ef34ba9, not its optional model-tuning alternatives.

1. Understand what you allocate

For every transformer layer, allocate a key tensor and a value tensor with shape:

[batch=1, number_of_KV_heads, cartridge_slots, head_dimension]

For an invented model with 8 KV heads, 256 slots, and head dimension 128, each layer stores \(2\times8\times256\times128=524{,}288\) scalar values. Multiply by layer count and dtype size for prefix storage. This excludes temporary query caches and optimizer state.

The slots are not necessarily representations of readable tokens after training. There is no JSON memory item or summary text to retrieve.

The released TrainableCache separates a frozen initial portion from the trainable portion; the factory's default freezes one initial token. It also tracks temporary keys/values generated by a training example or query. Only the learned prefix is the reusable cartridge. Cache class

2. Initialize the prefix from an ordinary model cache

One released option, KVFromText, does the following:

  1. Read an initialization text file.
  2. Render/tokenize it using the model's system-prompt conventions and chosen token budget.
  3. Prefill the frozen model to obtain keys and values.
  4. Wrap those tensors in TrainableCache, marking the configured initial slots frozen and the remainder trainable.

This starts with tensor values produced by the model, rather than an arbitrary array with the right shape. It does not mean the initialization text already summarizes the target corpus. Subsequent optimization teaches the cartridge that corpus. Initialization implementation

Save the backbone revision, tokenizer/chat template, initialization recipe, slot count, and frozen-slot count with the artifact. A cartridge is model-specific numerical state.

3. Generate self-study conversations from the corpus

The released self-study synthesizer samples a resource/subcorpus and seed prompts. It uses the model in two conversational roles:

  1. Role A sees the sampled source and a seed instruction, then generates a question or request about it.
  2. Role B sees that source and the accumulated conversation, then answers.
  3. Collect B's answer text and teacher token log probabilities.
  4. Optionally continue more rounds; repeat over source samples and seeds.

Both roles can have configured tools that add source information. Do not accidentally describe only the tool-free default as the entire system. Self-study implementation

For an invented operations manual:

Teacher source:
  Return window: 30 days.
  Damaged-item claims: notify support within 7 days.

A generates:
  What is the notification deadline for a damaged item?

B answers:
  Notify support within 7 days.

Saved:
  Conversation tokens + B's target-token positions
  + teacher top-token IDs/log probabilities at those positions.

Use varied questions and summaries so training exposes more than one wording of one fact. Coverage is a data-generation problem, not an automatic consequence of having a large prefix.

4. Build the student's different input

The teacher answered with source text in context. The student receives:

past_key_values = trainable cartridge
input tokens    = synthetic conversation, excluding the teacher's source context
target positions = designated assistant continuation tokens

Teacher-force the same preceding conversation tokens when matching the next-token distributions. “Teacher forcing” means that at an answer position, the student conditions on the recorded preceding answer tokens rather than its own sampled alternatives.

The student's source of corpus knowledge must be the cartridge. Leaving the full source text in the student's input makes the training task much easier but defeats the purpose.

The data loader handles packed sequences and maps target positions to the tokenized conversation. Preserve that mapping; source removal and chat-template tokens make naïve string offsets unreliable. Dataset implementation

5. Compute the actual released training signal

Conceptually, distillation minimizes teacher-to-student KL divergence:

\[ D_{\mathrm{KL}}(p_T\Vert p_C) =\sum_v p_T(v)\log p_T(v)-\sum_v p_T(v)\log p_C(v). \]

The first term is constant with respect to the cartridge. Therefore its gradient is obtained by minimizing the second, cross-entropy term.

The release uses stored top-token teacher probabilities, not an online full-vocabulary teacher forward pass in every training step. Its core calculation can be expressed as this PyTorch-shaped helper:

def cartridge_distillation_loss(logits, target_positions, token_ids,
                                teacher_logprobs, accumulation_steps=1):
    # Each array entry identifies one teacher-supported token at one position.
    # logits has shape [1, sequence_length, vocabulary_size].
    student_logprobs = logits.log_softmax(dim=-1)
    selected = student_logprobs[0, target_positions - 1, token_ids]
    weighted_ce = -teacher_logprobs.exp() * selected
    return weighted_ce.mean() / accumulation_steps

The minus one is essential: logits before target position \(j\) predict its token. This helper assumes the flattened aligned arrays used by the release; it is not a generic unpadded [batch,time,k] loss function.

The inspected calculation does not renormalize the stored teacher top-token mass. It averages the supported entries. Calling that exact implementation “full-vocabulary KL” would hide both the truncated support and reduction convention. Training loop

6. Backpropagate into the cartridge, not the backbone

For each batch:

  1. Freeze the backbone's parameters.
  2. Put trainable cache parameters, not backbone weights, in the optimizer.
  3. Run the student with the cartridge installed.
  4. Compute the distillation loss at supported target positions.
  5. Backpropagate and step the cache optimizer at the configured accumulation boundary.
  6. Clear the example's transient cache before the next independent example.

Do not wrap the student's entire forward pass in no_grad. Frozen weights still transmit gradients from the loss back to the input cache. Disabling autograd through that computation prevents the cartridge from learning.

The released optimizer selects cache.parameters() in cache-tuning mode. Its clear operation removes dynamic sequence state without erasing the learned prefix.

For packed batches, attention masks must allow each example to attend to the shared cartridge while preventing it from attending to another example. The release uses sequence IDs, including a dedicated cartridge sequence ID, to support this separation. Reusing only its tensor shapes without the mask semantics is insufficient.

7. Answer a new question

Load the trained prefix for the correct corpus and backbone. Start with a clean transient cache, append the new question using the compatible position/template convention, then decode normally.

In the example, “I received a damaged item—how soon must I report it?” should be answered from the cartridge even though that exact question was not a self-study prompt.

Reset transient state before another independent user's question. Otherwise user B can inherit user A's query or answer through the appended cache. Concurrent requests need separate dynamic cache state even if they share immutable prefix values.

A changed source manual is a changed cartridge-training target. This method does not automatically observe a file modification and rewrite one named fact.

8. Tests and feedback boundaries

  • Backbone weights have no gradients; trainable prefix slots do.
  • Frozen prefix slots remain unchanged after an optimizer step.
  • A synthetic one-position test confirms the causal shift.
  • Clearing a query removes dynamic entries but preserves learned prefix values.
  • Packed examples cannot attend across example boundaries.
  • Held-out questions test source coverage and paraphrases.
  • The student training prompt excludes the full teacher source.

The offline teacher sees source material and generates answers/distributions. Those answers supervise numerical prefix optimization. At deployment, no future query's gold answer is supplied and no per-query optimizer is required.

For implementation planning, the expensive new components are the synthetic-data pipeline and differentiable cache integration. The actual inference interface is simple: load prefix → append question → generate → discard query-specific cache.
