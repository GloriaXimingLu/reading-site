Still: turn an existing attention cache into a smaller one

2 min · 1 worked example · 2026-09-21

All methods

The idea: train a compression function, then apply it to new contexts' internal attention caches.

Unlike Cartridges, a new document does not require fitting a new numerical memory with gradient updates.

1. The frozen model reads the new context

Reading a document produces key/value tensors at each model layer. These tensors are the internal attention memory used when processing later tokens.

Suppose our invented context occupies 4,096 cache positions.

2. A trained compactor reads those tensors

The compactor receives the context's keys and values, not a written summary and not a future answer key.

Its learned slots attend to the original cache and combine information from it.

3. The compactor outputs a shorter cache

For example, it produces 256 positions of new keys and values.

These are synthesized values. The method does not simply choose 256 original tokens to keep.

4. The program installs the smaller cache

It replaces the full cache with the compact one.

It must preserve position information: although only 256 cache entries remain, the next token still follows the original 4,096-position context. Treating it as position 256 would change the model's positional calculations.

5. The model answers the question

Append the question and generate normally against the compact cache.

For this new context, the compactor runs forward once. There is no Cartridges-style fitting loop.

How was the compactor trained?

  1. A frozen teacher answers training questions with the full context cache.
  2. A student answers with the compactor's shorter cache.
  3. Compare their answer-token predictions and update only the compactor, teaching it which information to preserve.

The student backbone stays frozen, but gradients pass through it into the compactor. Training answers supervise that update; they do not become runtime compactor inputs.

What persists: the trained compactor parameters, reusable across contexts. Each new context gets its own compact cache.

Availability boundary: this explanation follows the paper. A compatible official code/checkpoint release was not verified in the audit.

The defining operation is: existing cache → trained compression function → smaller cache → ordinary continuation. Exact attention blocks, positional handling, and the separate streaming schedule are below.

All memory methods · Short overview

Cartridges optimizes a new prefix for a particular corpus. Still instead trains a compactor function once and applies that function to a new context's existing key/value cache. At deployment, the new context needs a prefill and compactor forward pass, not a new optimization run.

This is a paper-level implementation guide: a compatible official code/checkpoint release was not verified in this audit. The architecture and training description adapt Still, Sections 2 and Appendices A–F, licensed CC BY 4.0. The tensor example and integration tests are explanatory additions. Do not read the pseudocode as an upstream API.

1. Obtain the uncompressed cache

Run the frozen language model on the context, before the new question/continuation. For each layer you obtain:

K, V: [batch, KV_heads, original_context_length, head_dimension]

Use an invented single-batch example:

H = 8 KV heads
T = 4096 original positions
d = 128 values per head
t = 256 compressed positions
D = 256 compactor latent width

Each layer:
  input K/V:  [1, 8, 4096, 128] each
  output K/V: [1, 8,  256, 128] each

That is a 16-fold reduction in the prefix's K/V scalar count, not a claim of 16-fold end-to-end speedup. Prefill cost, compactor cost, attention kernels, and later query tokens still exist.

You need internal cache access and differentiable model execution for training. A text-only API cannot implement this architecture.

2. Remove the backbone's positional rotation from keys

Cached keys in a RoPE model already contain position-dependent rotations. Apply the inverse backbone RoPE at the original positions to get position-free keys. Values are not rotated.

Then concatenate keys and values along the feature dimension:

\[ X_h=[K_h;V_h]\in\mathbb{R}^{T\times 2d}. \]

In the example, each KV head gives a 4096×256 matrix. Concatenating along the time dimension instead would produce 8192×128 and implement a different operation.

The compactor's own RoPE, introduced next, is separate from the backbone's RoPE. Do not use the compactor's base 10 when undoing the backbone rotation.

3. Allocate learned latent slots and projection weights

Each transformer layer gets its own compactor. Within a layer:

  • A learned latent bank has shape \(H\times t\times D\).
  • Every KV head has its own latent slots.
  • Linear projections are shared across the layer's KV heads.
  • Different transformer layers do not communicate through a separate compactor channel.

The canonical configuration uses two residual blocks, cross-attention in both blocks, one cross-attention head, one latent self-attention head, and no feed-forward sublayer. The optional attention-bias channel is disabled.

Copy the latent parameters into the current computation, then update that activation through the blocks. Do not overwrite the learned parameters with each context's resulting latent state.

4. Compute one cross-attention update

For one KV head, let \(Z\) be its \(t\times D\) latent matrix. First apply non-parametric RMS normalization to its rows. Then:

\[ \widetilde Q=\operatorname{RMSNorm}(Z)W_Q+b_Q,\quad \widetilde K=XW_K+b_K,\quad V_X=XW_V. \]

Shapes are \(W_Q:D\times D\) and \(W_K,W_V:2d\times D\). Q/K projections have biases; the value projection does not.

Normalize each Q/K row to unit length. Apply the compactor's RoPE to Q at \(t\) positions evenly spaced across the original range, and to K at the original \(T\) positions. Its canonical RoPE base is 10.

Now compute:

\[ A=\operatorname{softmax}\left(DQK^\top\right),\qquad Z_1=Z+(AV_X)W_O. \]

The attention matrix is \(t\times T\). The multiplier is \(D\) after unit normalization, not the usual \(1/\sqrt D\). Using ordinary scaled dot-product defaults here would change the canonical architecture.

For multiple compactor attention heads, each head has width \(D\), not \(D/n_{\text{heads}}\); concatenate their outputs and project back to \(D\).

5. Mix latent slots, repeat, and project back to K/V

Apply latent self-attention to RMS-normalized \(Z_1\), using Q/K normalization and the same \(D\) logit scale, without RoPE, and add its output residually. Repeat the block.

Finally, separate linear heads map the resulting latent matrix to keys and values:

\[ C_K=Z_{\mathrm{out}}W_{\mathrm{key}},\qquad C_V=Z_{\mathrm{out}}W_{\mathrm{value}}, \]

where each output projection has shape \(D\times d\).

Reapply the backbone key rotation at the compact slots' evenly spaced positions over the original range. Again, do not rotate values. Install the resulting \(t\)-slot cache for that layer. Repeat across layers.

In mixed global/sliding-window backbones, the paper compacts global-attention layers while retaining the sliding-window layers' usual local cache semantics.

6. Preserve logical positions when installing the cache

After compressing 4096 positions into 256 entries, the next token is logically position 4096, not 256. Physical cache length and logical sequence length must be separate.

A small integration helper illustrates the offset contract:

def continuation_positions(original_length, physical_prefix_length, count):
    if not 0 <= physical_prefix_length <= original_length:
        raise ValueError("invalid compact-prefix lengths")
    if count < 0:
        raise ValueError("negative continuation length")
    offset = original_length - physical_prefix_length
    physical_positions = range(physical_prefix_length,
                               physical_prefix_length + count)
    return [position + offset for position in physical_positions]

For (4096, 256, 3) this returns [4096, 4097, 4098]. This is an explanatory position calculation, not a complete model cache class.

The integration layer must also construct attention masks, concatenate new dynamic K/V correctly, and use the backbone's expected cache layout. Naïvely assigning a shorter tensor while letting the model infer positions from its length can silently corrupt decoding.

7. Initialize near a pass-through before training

Still's identity-style initialization requires \(D=2d\):

  1. Initialize the first cross-attention value and output projections to pass through the concatenated K/V features.
  2. Initialize the final key/value projections to select the respective feature halves.
  3. Zero the latent bank and cross-attention key projection; align the query/key biases.
  4. Let the compactor's positional rotations produce localized initial attention.
  5. Zero the self-attention output projections and later cross-attention output projections so those residual branches initially contribute nothing.

At \(t=T\), this should behave approximately like retaining the original cache. It is not an exact identity guarantee: attention still mixes positions. At \(t<T\), each latent initially pools a local region.

This gives you a useful first diagnostic: a catastrophic answer-quality drop at equal input/output lengths suggests cache integration, rotation, or initialization problems before compression difficulty becomes the explanation.

8. Train with full-context teacher versus compact-cache student

A training example contains context tokens, question/prompt tokens, and answer tokens. The paper constructs context-dependent MCQs, verifies them with the frozen teacher, and filters questions answerable without the context.

For each example:

  1. Prefill the frozen backbone on context to obtain full K/V.
  2. Teacher path: answer the question against full K/V and retain answer-side token distributions.
  3. Student path: pass that same context K/V through Still, install the compact cache, and teacher-force the question and target answer.
  4. Compute forward KL from teacher to student only on answer-side positions.
  5. Backpropagate through the student backbone into Still.
  6. Update only compactor parameters; leave backbone weights frozen.

The canonical loss uses the teacher's top-200 vocabulary support with the gold answer token forced into that support. Prompt and padding positions are masked. The paper does not specify every numerical support/normalization implementation detail sufficiently to call a new implementation bit-identical; make those conventions explicit in a reproduction.

The compactor's direct input remains context K/V, not the question or gold answer. The gold answer and teacher distributions affect its parameters through training. At inference on a new context, neither is needed.

As with Cartridges, frozen backbone parameters do not justify putting the entire student forward pass in no_grad: gradients must pass through its attention computations back to the compact cache.

9. Implement streaming as a separate schedule

The paper's iterative setting is not “repeatedly squeeze everything into the same 256 slots.” For ratio \(c\), compact each raw block of \(c\,t\) tokens into \(t\) entries while retaining accumulated compact blocks.

In its lookahead schedule:

  1. Prefill two raw blocks.
  2. Compact the older block; retain the newer raw block as lookahead.
  3. Prefill another raw block conditioned on the compact prefix and retained raw state.
  4. Compact the previously retained block.
  5. Repeat.

The new raw block's states were computed with the existing compact history; this differs from independently prefilling all chunks and concatenating their summaries. Cache size grows roughly with \(T/c\), plus a raw lookahead block.

Iterative training is also a separate recipe, including rollout through repeated compaction and reported stabilization variants. Do not assume a single-pass checkpoint is validated for arbitrarily many recursive applications.

10. Tests before interpreting model quality

  • Feature concatenation and output shapes match every layer/head.
  • Inverse then forward backbone RoPE recovers keys within numeric tolerance.
  • The compact slots use mapped original positions; continuation starts at original length.
  • Student loss produces compactor gradients but no backbone gradients.
  • Teacher targets and gold answers never enter the compactor's inference input.
  • Equal-length initialization is approximately pass-through.
  • Independent queries do not inherit each other's dynamic cache.
  • Iterative and independent-chunk schedules are evaluated separately.

The complete path is context prefill → per-layer K/V resampling → position-correct cache replacement → ordinary question answering. The practical work is in implementing that cache contract, not in writing a summarization prompt.
