Q&A: Hyperagents

Session 2026-08-24

Q: What does "continuing DGM-H for 200 iterations on math grading from transfer hyperagents reaches 0.640 vs 0.610 from scratch" mean?

A: It is the compounding experiment. Two 200-iteration DGM-H runs on the same task (math grading), differing in exactly one thing — what they start from:

Arm Starting point Final score
Seeded hyperagents that had already evolved in a different domain 0.640
From scratch the plain minimal seed agent 0.610

What it tests. The promise of recursive self-improvement is that gains accumulate: an agent that has already learned how to improve things should make the next round of improvement go better, even on an unrelated task. So does handing a fresh run a set of already-evolved improvers — carrying the memory tools, performance trackers and prompt templates they invented — get further than starting cold?

The answer is barely, and not reliably. A +0.03 gap, reported as a higher median but not statistically significant. With five runs on a heavy-tailed distribution, that is consistent with no real effect.

Why it is the most important number in the Results section. Every other result shows improvement working within a run — paper review 0.0 → 0.710, the meta-transfer result at imp@50 = 0.630 against near-zero controls. Those are real, but they all say "one round of improvement helps." Compounding is the claim that round N+1 benefits from round N, which is what would make the curve bend upward instead of flattening. This is the paper's own attempt to demonstrate that, and it comes back inconclusive.

That is why Weco's "4 Levels of RSI" taxonomy files Hyperagents at Level 0 — concept demonstration, not measured net-positive acceleration — and why the critical take says the gains so far amount to recovering standard engineering practice (logging, notes, templates), with no evidence the curve continues past it.

One thing to keep separate: the numbers that follow in the same bullet — 0.700 vs 0.670, and BetterGrader's 0.561 → 0.601 — are a different experiment. Those seed from a strong task-specific baseline (ProofAutoGrader), which shows the loop can improve an already-good system. That is not the same as showing improvement compounds. The tutorial now splits these into two bullets, because running them together invites exactly this confusion.
