Q: "An agent's source code plus scaffolding" — what is source code and what is scaffolding?

A: The paper does not draw a hard line. It defines the genotype loosely as "an executable coding agent together with its auxiliary scaffolding," and in practice the whole editable codebase is fair game. The distinction people usually intend is:

  • Source code — the agent's own program: the main loop, the entry point, retry and error handling, how model output is parsed, how the agent decides it is finished. Code the agent executes.
  • Scaffolding — everything wrapped around the model call that is not the model: prompt templates, tool definitions and their contracts (a bash tool, an edit tool), memory and context assembly, output validators. Code and text that shapes what the model sees and can do.

Why the boundary stays fuzzy, and why the paper does not police it:

  • A prompt template lives in a .py file, so it is literally source code while functionally being scaffolding. When an agent adds num_candidates=3 plus a ranking step, that is simultaneously new control flow and a new tool contract.
  • The paper is drawing a different line, and it is the one that carries weight: scaffold versus backbone. The Qwen3.6-35B weights never change. Everything in the genotype is code and text around a frozen model — hence the abstract's "purely through evolving the agent scaffold," and hence an evolved scaffold can be lifted onto DeepSeek-V4-Pro and still perform (96.9%).

For reading purposes, treat "source code plus scaffolding" as one thing — the agent's whole editable repository — and keep the contrast that does real work: the repository evolves, the model weights do not. The same framing governs DGM, where the frozen-FM constraint is what makes the archive cheap to keep.

Q: The node-level Beta posterior equation — what do the symbols mean?

A: The equation is

\[\pi_a\sim\mathrm{Beta}\big(\kappa(1+n_{\mathrm{s}}(a)),\;\kappa(1+n_{\mathrm{f}}(a))\big)\]

and it encodes a belief about a single number: what is agent \(a\)'s true success rate?

Symbol Meaning
\(n_{\mathrm{s}}(a)\) how many tasks agent \(a\) has solved
\(n_{\mathrm{f}}(a)\) how many it has failed
\(\mathrm{Beta}(\cdot,\cdot)\) the standard belief distribution over a rate, given a count of wins and losses
\(\pi_a\) one random draw from that belief — a guess at the agent's true rate
\(\kappa\) scales how confident the belief is
the \(1+\) a uniform prior, so an agent with no record could be anything from 0 to 1

Mechanically: every candidate draws one \(\pi_a\), and the highest draw is selected. That is Thompson sampling, and the width of each belief does the exploring — there is no separate exploration parameter.

  • Evaluated twice, one success → broad belief → draws swing wildly → it keeps getting picked despite a mediocre record, because its uncertainty is worth resolving.
  • Evaluated forty times, twenty successes → same 50% rate, narrow belief → draws cluster near 0.5 → it stops absorbing evaluations.

What \(\kappa\) does: it multiplies both counts, changing confidence without changing the implied rate. Below 1 it pretends there is less evidence than there is, widening the belief toward exploration; above 1 it sharpens toward the observed rate. The paper never states its value — inherited from HGM and unrestated, the same gap as \(\alpha\).

The clade-level version is the identical formula with counts summed over the agent's whole subtree rather than the agent alone. That single substitution is what makes a 1-of-3 agent with 20-of-25 descendants an attractive parent to expand: its own record is weak, but the evidence its branch is fertile lives in its children.
