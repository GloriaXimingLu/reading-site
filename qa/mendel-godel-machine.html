Q&A: Mendel Gödel Machine

Session 2026-08-24

Q: "An agent's source code plus scaffolding" — what is source code and what is scaffolding?

A: The paper does not draw a hard line. It defines the genotype loosely as "an executable coding agent together with its auxiliary scaffolding," and in practice the whole editable codebase is fair game. The distinction people usually intend is:

  • Source code — the agent's own program: the main loop, the entry point, retry and error handling, how model output is parsed, how the agent decides it is finished. Code the agent executes.
  • Scaffolding — everything wrapped around the model call that is not the model: prompt templates, tool definitions and their contracts (a bash tool, an edit tool), memory and context assembly, output validators. Code and text that shapes what the model sees and can do.

Why the boundary stays fuzzy, and why the paper does not police it:

  • A prompt template lives in a .py file, so it is literally source code while functionally being scaffolding. When an agent adds num_candidates=3 plus a ranking step, that is simultaneously new control flow and a new tool contract.
  • The paper is drawing a different line, and it is the one that carries weight: scaffold versus backbone. The Qwen3.6-35B weights never change. Everything in the genotype is code and text around a frozen model — hence the abstract's "purely through evolving the agent scaffold," and hence an evolved scaffold can be lifted onto DeepSeek-V4-Pro and still perform (96.9%).

For reading purposes, treat "source code plus scaffolding" as one thing — the agent's whole editable repository — and keep the contrast that does real work: the repository evolves, the model weights do not. The same framing governs DGM, where the frozen-FM constraint is what makes the archive cheap to keep.
