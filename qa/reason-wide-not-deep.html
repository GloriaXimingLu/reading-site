Q&A: Reason Wide, Not Deep: Amortizing the Reasoning Premium into Distilled Skills

Session 2026-08-12

Q: The paper distills a bunch of skills. At test time, how does the system decide which skill to use for which question?

A: It doesn't — there is no test-time skill selection mechanism, and that's by design. Skills are scoped per model×domain, not per question: distillation runs once per domain (from 35–50 training-task rollouts) and produces one consolidated skill document. At test time that whole document is appended verbatim to the system prompt for every question in the domain ("nothing else — harness, decoding, tools — changes"). Any per-question "selection" happens implicitly inside the model's forward pass as it reads the rules in context; the only explicit routing decision is the deployer's choice of which domain's skill file to load. The payoff is systems-level: the skill is a cacheable prefix (sits in KV cache once, near-zero marginal cost per episode), which is what "amortizing the reasoning premium" means operationally.

Limitations to keep in mind: no fallback for uncovered questions, no cross-domain skill composition, and no ablation of concatenation vs. top-k retrieval vs. learned routing — so whether flat concatenation holds up at large skill-library sizes is untested. Retrieval-based skill systems in this tracker (MSCE, Living-Harness's retrieval-only reuse) are the natural contrast points where selection is explicit.
