Session 2026-09-18

Q: How do ShadowFrog, Claude-Mem, and Codex compaction differ for an inner task-solving agent?

A: ShadowFrog has the solver write source-addressed Markdown discoveries and use file-aware reminders/read/search to recall them. Claude-Mem has a separate observer turn tool events into structured notes; the solver searches a small index and fetches selected details. Codex compaction replaces active conversation state, through either readable summarization or a provider-native opaque representation. External notes and compaction are complementary: a note store does not by itself stop the active context growing.

Q: Does ShadowFrog implement “save notes, reset context, and resume”?

A: Not as a complete controller in the inspected release. Its hooks cover session start and edit-tool pre-use. The solver writes discoveries under skill instructions. Adding a guaranteed pre-reset write/flush operation and a context-replacement policy is our adaptation. Its 97.6% versus 36.2% result concerns planted-fact retrieval under a supplied-path/tool-budget condition, not task success or automatic note-writing quality. See the source-grounded steps.

Q: Does Claude-Mem save everything without compression?

A: No. The observer selects and compresses findings. There is also best-effort raw tool-I/O storage and fetch, but filters, missing IDs, failures, and caps can limit it. The inspected code caps each tool input/result field at 64 KiB; an earlier documentation-level description as a per-row cap was imprecise. Notes and search indexing are asynchronous, so a controlled reset experiment needs an explicit readiness barrier. See the implementation caveats.

Q: Is Codex compaction just a summary plus recent tool results?

A: Not universally. The checked readable path retains selected real-user messages and a generated handoff, with initial-context handling; it does not generally retain a raw tool-result tail. Provider-native compaction produces opaque state and may retain other items. A portable baseline with a checkpoint plus complete recent tool exchanges is our proposed adaptation, not an exact reproduction. See the two paths.

Q: Which initial versions are useful without locking the full design yet?

A: Checkpoint-only; checkpoint plus solver-written notes; checkpoint plus observer-written notes. Keep the reader interface and checkpoint policy fixed when comparing the latter two. Add stable-ID evidence recovery separately to test whether discarded detail is the bottleneck. These are proposed versions, not implemented systems or measured winners. Within-task continuity and cross-task experience reuse require separate reset/evaluation protocols. See the shortlist.

Session 2026-09-20

Q: Does a memory writer see the ground-truth answer or environment feedback?

A: There is no universal rule. Ordinary observations, an LLM's self-judgment, external outcome scores and full reference answers are different signals. ShadowFrog records what the solver observes; Claude-Mem records supplied events. ReasoningBank explicitly uses a no-reference LLM judge. ACE reports both GT-label and no-label Reflector settings. MemRL uses environmental rewards for utility updates, but that does not establish the summarizer's exact gold-answer visibility; check the benchmark adapter. See the source-linked comparison.

Q: If training uses ground truth, does the writer see it while writing?

A: Not necessarily. MemAgent and ContextPilot generate memory/context actions from their available inputs; ground truth scores final answers for training. MemexRL uses task-outcome reward to train earlier memory actions. Reward-based parameter updates and answer-key text in a writer's prompt are different information channels.

Q: Can an online memory system receive the correct answer after an attempt?

A: Yes, if the protocol explicitly allows supervised feedback. Record task A's score first, reveal the permitted feedback, update memory, then attempt B. A feedback-assisted retry of A is a separate condition. Do not compare this to observation-only memory as though both had equal information.

Q: Are V0–V3 faithful reproductions of the named methods?

A: No. The earlier suggested sequence is a set of controlled adaptations/ablations, not a locked plan. A faithful port preserves writer inputs, prompts, timing, schema, retrieval, context replacement, feedback and persistence rules. Removing packaging may preserve behavior; changing those contracts generally does not. Read the step-by-step tutorial before choosing adaptations.

Q: Which newly checked details change an implementation?

A: ACE can receive gold-derived correctness feedback even with answer text hidden, and its adaptation loop can retry the same example. MemAgent's stated DAPO advantage subtracts the group mean without dividing by standard deviation. Cartridges' trainer uses stored teacher top-token probabilities and indexes student logits one position before the target.
