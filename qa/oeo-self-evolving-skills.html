Q&A: Rethinking Self-Evolving Agents (OEO)

Session 2026-08-20

Q: Does OEO do harness optimization (editing the agent's entire code) or just skill optimization (the skill file only)?

A: Skill optimization only — the harness is completely frozen. The mutable artifact is a persistent natural-language skill: a Markdown text document injected into the target model's context. The optimizer's action space over the artifact is limited to Revise(s′) (commit a new version of the skill text), Select(j) (choose a checkpoint), Inspect, RunTarget, and Stop; the contract fixes the objective, target model, permitted operations, budget, frozen evaluator, and sealed eval split, and does not permit modifications to the agent's control loop, tools, or memory system. The paper doesn't position itself against harness-optimization work at all.

The naming is a bit of a trap: OEO's "open-endedness" refers to the optimization process — the frontier optimizer composes its own improvement procedure instead of following a prescribed analyze→edit→validate pipeline — not to the scope of what can be edited.

Placement in the harness-optimization walkthrough taxonomy: OEO belongs to the skills line of Thread A (alongside MSCE, Skill Self-Play, and Evo-Harness's skill compilation), not with RHI / DarwinX / Living-Harness, which mutate harness content or structure. Open transfer question: OEO shows frontier optimizers do better without prescribed pipelines at a median 34.3% of the reference interaction budget — whether that survives when the mutable object is the harness itself (where DarwinX and RHI still impose prescribed evolutionary/pairwise pipelines) is untested.
